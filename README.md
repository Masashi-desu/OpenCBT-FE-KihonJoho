# OpenCBT-FE-KihonJoho

基本情報技術者試験（FE）の学習とCBT形式の操作練習を行う、非公式のフロントエンドアプリです。IPA・プロメトリック・試験運営事業者とは関係ありません。

**公開アプリ：[OpenCBT FEを開く](https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/)**

公開情報をもとにCBTの画面・操作を再現しています。実際の試験画面・動作とは異なる場合があります。解答・復習画面のフッターには出典、改変区分と必要な権利文言を表示し、展開すると素材別の条件や改変概要を読めます。「出典・改変詳細」と「ライセンス表記」は展開部分から同じ画面で開いて閉じられます。

2023〜2026年度のIPA公開問題103問と、それらの画像・記述を基に作図・バインド・正答生成を行う103種類の改変テンプレートを収録しています。2025年度科目B問6はJIS文言の利用条件未確認のため除外しています。公開問題は本番の全問題ではありません。原問題の詳細解説は2023年度科目A問1・問11、2024年度科目A問13、2026年度科目A問2に用意し、他の原問題にはまだ収録していません。正答表示・復習時の「用語の補足」では、英字略語の正式名称と日本語の意味、他の選択肢に関連する用語を確認できます。年度別問題・生成問題・保存済みの問題で利用できます。

通常解説から問題専用のHTML/CSS/JSによる詳細解説画面へ遷移できます。2026年度科目A問2には、7種類のソートを比較・再生・巻き戻しできる[ソート解説・動作シミュレーター](docs/sort-explanation.md)を用意しています。2024年度科目A問13の[アローダイアグラム解説](docs/arrow-explanation.md)では、図上で作業日数とダミーを変更し、最早・最遅時刻、余裕時間、クリティカルパスを計算できます。生成問題では保存された対象・数値に合わせて初期表示します。詳細解説画面では出典・ライセンス・改変情報を常時展開します。[共通基盤の仕様](docs/detailed-explanations.md)を参照してください。

2023年度科目A問1の[基数変換解説](docs/radix-explanation.md)では、2・8・10・16進数の整数・小数・負数・循環小数を相互変換し、桁の重みと加算・割り算・掛け算を操作しながら確認できます。正確な分数で計算し、循環は括弧で、出力の小数部64桁での切り捨ては近似記号と省略記号で区別します。

2023年度科目A問11の[流れ図解説](docs/flow-explanation.md)では、初期値と比較条件を変更し、分岐・減算・文字式・印字結果を1処理ずつ確認できます。公開問題の4選択肢を試し、2a＝3bなどの関係式を実際の経路から導出して、基準問題の指定経路と比較できます。実行履歴を戻って復元できます。

メニューの「模擬試験」の下にある「検索」から、公開問題と詳細解説を用語・本文で探せます。科目・年度・問題／詳細解説で絞り込み、検索結果から問題・正答・通常解説・詳細解説を閲覧できます。問題の下には操作ボタンをまとめ、出典情報を常時表示します。「類題を解く」から条件を変えた問題の練習を始められます。検索と閲覧自体は練習や回答記録を作成せず、条件とページをURLに保持します。[検索の仕様](docs/search.md)を参照してください。

## 起動

Node.js 22.x又は24.xとnpmを使います。検証環境はNode.js 24.10.0／npm 11.6.0です。

```sh
npm ci
npm run dev    # アプリ。既定 http://127.0.0.1:5175/
npm run doc    # 仕様書。既定 http://127.0.0.1:5173/
```

別々のターミナルで起動します。両方ともループバックで待ち受け、ポート使用中は空きポートと実際の閲覧URLをログに表示します。停止はCtrl+Cです。

年度別オリジナルとランダムミックスを選べます。年度別は原文・元の数値を維持します。ミックスは分野構成を保ち、全問の本文・図・選択肢・正答・解説をパラメータから生成します。固定問題の並べ替えと独自学習問題の選択肢は廃止しました。選択肢の行を押して解答します。丸いラジオボタンと右端のチェックは表示せず、選択肢の本文・図表の表示幅を確保します。選択中は太い枠と背景で示します。選択済みの行を再選択すると解除でき、解答欄下部の旗アイコンで見直しを切り替えられます。ヘッダー上段にロゴ・科目／モード・練習名とブックマーク・一時停止・正答表示・問題一覧を置きます。資料一覧・手ボタン・＋／−・ズーム選択は問題資料の上に、時計・終了操作は解答領域の上に置き、PCでは左右の高さと境界を揃えます。スマホでは上段、資料の表示操作、問題資料、時計・終了操作、解答領域の順に縦に並び、どのヘッダーも上部に固定せずスクロールします。資料一覧からページを選び、手ボタンで本文・図表をドラッグしてスクロールできます。ズームは左の問題資料へ適用し、自動・実際のサイズ・ページに合わせる・幅に合わせる・50〜400％を選べます。本文・図表は問題資料に一度だけ表示し、解答領域には問題番号と選択肢をまとめます。復習や狭い画面でも重複表示しません。時間付き練習は中断中も期限が進み、終了後に学習正答率を表示します。公式IRT評価点・合否は算出しません。

最初に「学習・復習」「時間付き練習」「無限周回」を選び、科目を選びます。通常の2モードでは出題セット・年度・出題数を表示します。無限周回では年度・出題数を指定せず、選んだ科目の収録系列から毎回ランダムに問題定義を選び、条件を変えて出題します。同じ系列が続けて選ばれる場合もあります。1問から開始し、「次へ」で新しい条件の問題を同じ練習へ追加します。前の回答を保持し、終了時に全問をまとめて集計します。再開・復習では生成済みの問題を使います。通常モードへ戻ると、直前の年度・出題数・出題セットの選択を復元します。

サイドバー下部（狭い画面ではフッタ）の太陽・月でライト／ダークモードを切り替えられます。両モードとも白・黒・グレーを基本色とし、正誤・注意・エラーなど意味を伝える色は保持します。表示設定はこのブラウザに保存し、再読み込み後も保持します。

画面で共有する色は[src/ui/tokens.css](src/ui/tokens.css)を正本とし、通常画面・詳細解説・スクロールバー・仕様書はCSS変数を参照します。画面側に固定色や色のフォールバックを重複定義しません。追加・変更時は[共通色の規約](docs/screens.md#共通色の定義と利用)と`npm run colors:check`に従います。

すべての画面・ダイアログ・図表と仕様書で、標準スクロールバーを隠し、幅6pxの半透明バーを前面へ重ねて表示します。バー用の幅・高さを確保せず、表示領域を圧迫しません。縦横のドラッグ、ホイール・タッチ・キーボードによるスクロールを使えます。

生成問題は原問題の出力形式を崩さずに抽象化します。問いの方向、正誤条件、解答対象、選択肢の役割と数を固定し、対象・条件・値を同じ役割の位置へ埋め込みます。例えば「クイックソートの処理方法を説明したものはどれか。」は、ソートの対象を変えても処理方法の説明を選ぶ問いを維持します。文章は文章へ、箇条書きは箇条書きへ値を埋め込み、元からある表・図・空欄付き疑似言語を保持します。解法の補助表や図の接続説明は出題本文へ追加しません。アローダイアグラムの円・上下ラベル・破線・凡例、文章図の見出し・箇条書きを維持し、代替説明は読み上げ用に保持します。保存済みアローダイアグラムにも表示互換を適用し、数値・正答を変えません。全103系列の問い方と注意書きを原資料と照合し、記号の定義・前提・入力域・添字・未定義要素・単位・端数処理・繰返しの非実行条件も解答前の本文・図表へ保持します。条件を変えた場合は関連する注記も同時に更新します。計算問題は原問題の桁数と選択肢の間隔を基準にし、手計算しやすい入力を生成します。損益計算や理論度数に原問題にはない細かい丸めを追加しません。新規開始の計算12系列は生成器2.2.0／3.3.0、他の系列は2.1.0／3.2.0を使います。公開済み2.1.0／3.2.0の保存内容・正答は保持し、旧版での再開・復習・問題追加を検証します。正答の一意性に問題があった旧4系列は取り下げ通知の対象とし、その旧版を含む保存記録は更新確認時に削除します。

ミックスは収録済み103問すべて（科目A80・科目B23）の登録テンプレートに対応しています。数値・引数・図の条件に加え、知識問題では原問題の問い方・判定条件を保ったまま対象や状況を変え、選択肢・正答・独自解説を一緒に生成します。生成版は改変問題であり、公式原文の再録とは区別します。[問題別の対応一覧](docs/generation-coverage.md)は配布データと登録契約から生成・検証します。同じテンプレートの異なる入力を出題できます。抽選器が生成した有効な入力は、基準問題と同じ入力・正答であることだけを理由に除外しません。計算問題の抽選候補は系列別の刻み・相関条件に従います。問題数が決まるミックスでは同じ練習と直前セッションの入力を避けます。無限周回と個別のブックマーク練習では同系列の直前の入力を避け、過去の条件を再利用できます。正答を変えられる問題では直前の正答値も避け、選択肢順を抽選します。四つの産業財産権のように正答が固定された問いは、その列挙形式を保ち、誤答候補の権利を変えて生成します。原問題とバインド前の完全な基準問題を保存し、全生成問題を改変ありと記録します。再開・復習で再生成しません。解答・結果は端末内のIndexedDBに保存し、最終更新から180日で削除します。履歴は「すべて」「年度別問題」「ランダムミックス」「ブックマーク練習」で絞り込めます。初期表示は「すべて」です。履歴で1件／全件削除できます。

解答・復習画面のヘッダーにあるブックマークボタンで、繰り返し練習したい問題を保存できます。結果画面では未解答と不正解の問題をそれぞれまとめて追加できます。一覧には元問題の文頭と、ストラテジなどの分野名を表示します。分野名の右隣には、複数の学習テーマと、教科書・参考書の索引で探すための検索語を表示します。ブックマーク一覧の上には科目・分野のフィルタを左寄せで置き、両方の条件に一致する問題を表示します。科目はすべて・A・B、分野はすべて・テクノロジ・マネジメント・ストラテジ・アルゴリズム・情報セキュリティから選べます。「表示中のブックマークの類題を練習」では、開始時に表示している問題だけを候補に、毎回ランダムに問題定義を選んで類題を生成します。該当する問題がなければ開始できず、フィルタを解除して全件表示へ戻せます。科目A・Bの両方を含められ、開始後にブックマークを追加・削除してもその練習の対象は保持します。メニュー左列の「ブックマーク」から個別の問題を開くと類題を生成し、「次の類題」で条件を変えた問題を連続して解けます。問題数を制限しない学習の共通処理で、同じ練習へ類題を追加します。前の問題へ戻って回答を見直せ、終了時には追加した全問をまとめて集計・保存します。再開・復習では生成済みの内容を使います。ブックマークは履歴と別に保存し、履歴削除や180日の期限では削除しません。ブックマークの削除又はサイトの保存領域の消去で削除できます。利用できなくなった原問題の参照は更新確認時に削除します。

ブックマーク一覧には、終了した練習の回答から問題ごとに直近20件を上限とした正答率と正解数／回答数を表示します。年度別問題・ランダムミックス・ブックマーク練習の回答を元問題ごとにまとめ、未解答と無効な記録は除きます。回答履歴がなければ「回答履歴なし」と表示します。履歴の削除・180日の保存期限によって集計対象も減ります。

## 検証・ビルド

```sh
npm run test           # 出題・生成・期限・正答・不正データ
npm run colors:check   # 共通色の利用、変数の定義、詳細解説の複製の一致
npm run data:validate  # 本体配布データ・参照・画像・権利記録
npm run build          # 検証・型確認後、distへ静的ビルド
npm run preview        # distを127.0.0.1:4175で確認
npm run doc:build      # 文書・Schema・35サンプル・51不正例の検証とビルド
npm run doc:reference  # Schema変更後のフィールド辞書再生成
npm run doc:generation # 配布データと登録契約から生成対応一覧を更新
npm run check          # 本体テスト・ビルド・文書ビルドをまとめて実行
```

## 開発規約

[AGENTS.md](AGENTS.md)と、リポジトリ内の[FE問題の全件生成対応スキル](.agents/skills/fe-question-generation/SKILL.md)に従います。対象範囲内で用意可能な問題の全件対応を完了条件とし、配布検証で維持します。メニューへ対応件数やバインド方式の説明欄を追加する運用は行いません。

詳細解説の追加・改修は[詳細解説UIの実装規約](docs/detailed-explanations.md#詳細解説uiの実装規約)を初回実装から適用します。追加の指摘を待たず、学習の焦点から必要な図・操作・関連パターンを設計し、重複する記載を省いて現在の確認対象へ注意を向けられる表示にします。主図の全幅、操作位置の安定、状態に連動する説明、共通ホストでの単一ページスクロールを守り、個別の寸法やボタン構成を全解説へ固定しません。機能・配置と併せて注意の向けやすさを検証します。

作問の品質判定は[問題作成・可変問題の品質規約](docs/question-authoring.md)を正本とします。既存の可変問題の修正と今後の公開問題・年度追加に適用し、計算精度・負担、誤答の意味と間隔、文章・図表の前提、生成候補の容量、独立検算、素材条件、保存互換を査読・テストします。現在の件数や今回の計算問題の刻みを、将来の全問題へ固定した規則として流用しません。

問題や生成器の追加・変更では、計算・アルゴリズムを独立した参照解法で照合し、知識選択を査読済みの対応資料で検証する自動テストを必須とします。全選択肢の成立条件、正答の一意性、本文・図・解説との整合を確認します。[必須テストの規約](docs/acceptance.md#生成内容と正答の必須テスト)に従い、テスト未整備・失敗のまま配布しません。

## GitHub Pages

静的ビルドとハッシュ形式の画面遷移を使い、リポジトリのサブディレクトリから配信できます。バックエンド、認証、課金はありません。

公開先は [https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/](https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/) です。**mainへのpushで自動デプロイ**します。[ワークフロー](.github/workflows/pages.yml)がNode.js 24で依存を導入し、test・配布検証・型確認・buildが成功した後にdistを配信します。実行結果は[GitHub Actions](https://github.com/Masashi-desu/OpenCBT-FE-KihonJoho/actions/workflows/pages.yml)で確認できます。

GitHub側の初期設定はSettings → Pages → Sourceの **GitHub Actions** です。再デプロイする場合はActions → **Deploy OpenCBT to GitHub Pages** → **Run workflow**でmainを選びます。main以外のブランチでは配信しません。`npm run build`はローカルの静的ビルドです。

## 仕様・出典・利用条件

OpenGraph画像、共有メタ情報、Web App Manifest、ロゴ・ファビコンは`npm run assets:generate`でまとめて生成し、`npm run assets:check`で正本との一致を確認します。文字・配置・配色・公開URLの正本は`scripts/brand/site.json`です。[共有資産の管理](docs/sharing-assets.md)を参照してください。dev・buildでは自動再生成し、test前に鮮度を検査します。生成用フォントはリポジトリへ同梱せず、初回にCDNから固定版を取得してhashを検査し、`.cache/brand-fonts/`へ保存します。`npm run fonts:prepare`で事前取得でき、以後はキャッシュを再利用します。閲覧時のフォント通信は追加しません。

ロゴとファビコンは`npm run icons:generate`で再生成できます。資格コード、色、文字の位置・寸法、フォント、出力先を指定できます。[生成方法](docs/brand-icons.md)を参照してください。
