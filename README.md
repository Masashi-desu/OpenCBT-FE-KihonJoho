# OpenCBT-FE-KihonJoho

基本情報技術者試験（FE）の学習とCBT形式の操作練習を行う、非公式のフロントエンドアプリです。IPA・プロメトリック・試験運営事業者とは関係ありません。

2023〜2026年度のIPA公開問題103問と、それらの画像・記述を基に作図・バインド・正答生成を行う103種類の改変テンプレートを収録しています。2025年度科目B問6はJIS文言の利用条件未確認のため除外しています。公開問題は本番の全問題ではありません。原問題の詳細解説は未収録です。

## 起動

Node.js 22.x又は24.xとnpmを使います。検証環境はNode.js 24.10.0／npm 11.6.0です。

```sh
npm ci
npm run dev    # アプリ。既定 http://127.0.0.1:5175/
npm run doc    # 仕様書。既定 http://127.0.0.1:5173/
```

別々のターミナルで起動します。両方ともループバックで待ち受け、ポート使用中は空きポートと実際の閲覧URLをログに表示します。停止はCtrl+Cです。

年度別オリジナルとランダムミックスを選べます。年度別は原文・元の数値を維持します。ミックスは分野構成を保ち、全問の本文・図・選択肢・正答・解説をパラメータから生成します。固定問題の並べ替えと独自学習問題の選択肢は廃止しました。学習は正答表示・一時停止が可能です。時間付き練習は中断中も期限が進み、終了後に学習正答率を表示します。公式IRT評価点・合否は算出しません。

サイドバー下部の太陽・月でライト／ダークモードを切り替えられます。表示設定はこのブラウザに保存し、再読み込み後も保持します。

生成問題は原問題の出題形式を維持します。文章は文章へ、箇条書きは箇条書きへ値を埋め込み、元からある表・図・空欄付き疑似言語を保持します。解法の補助表や図の接続説明は出題本文へ追加しません。アローダイアグラムの円・上下ラベル・破線・凡例、文章図の見出し・箇条書きを維持し、代替説明は読み上げ用に保持します。保存済みアローダイアグラムにも表示互換を適用し、数値・正答を変えません。形式修正前の保存記録は当時の内容で再開・復習し、新規開始には既存13系列の生成器2.0.0、追加86系列の3.0.0、査読で修正した4系列の3.0.1を使います。正答の一意性に問題があった旧4系列は取り下げ通知の対象とし、その旧版を含む保存記録は更新確認時に削除します。

ミックスは収録済み103問すべて（科目A80・科目B23）の登録テンプレートに対応しています。数値・引数・図の条件に加え、知識問題では対象・対応関係・問う方向を変え、選択肢・正答・独自解説を一緒に生成します。生成版は改変問題であり、公式原文の再録とは区別します。[問題別の対応一覧](docs/generation-coverage.md)は配布データと登録契約から生成・検証します。同じテンプレートの異なる入力を出題できます。直前に保存した同テンプレートのセッションで使った入力を避け、直前の正答値も繰り返さず、選択肢順を抽選します。原問題とバインド前の完全な基準問題を保存し、全生成問題を改変ありと記録します。再開・復習で再生成しません。解答・結果は端末内のIndexedDBに保存し、最終更新から180日で削除します。履歴で1件／全件削除できます。

## 検証・ビルド

```sh
npm run test           # 出題・生成・期限・正答・不正データ
npm run data:validate  # 本体配布データ・参照・画像・権利記録
npm run build          # 検証・型確認後、distへ静的ビルド
npm run preview        # distを127.0.0.1:4175で確認
npm run doc:build      # 文書・Schema・35サンプル・51不正例の検証とビルド
npm run doc:reference  # Schema変更後のフィールド辞書再生成
npm run doc:generation # 配布データと登録契約から生成対応一覧を更新
npm run check          # 本体テスト・ビルド・文書ビルドをまとめて実行
```

## 開発規約

[AGENTS.md](AGENTS.md)と、リポジトリ内の[FE問題の全件生成対応スキル](.agents/skills/fe-question-generation/SKILL.md)に従います。対象範囲内で用意可能な問題の全件対応を完了条件とし、配布検証で維持します。メニューへ対応件数やバインド方式の説明欄を追加する運用は行いません。

問題や生成器の追加・変更では、計算・アルゴリズムを独立した参照解法で照合し、知識選択を査読済みの対応資料で検証する自動テストを必須とします。全選択肢の成立条件、正答の一意性、本文・図・解説との整合を確認します。[必須テストの規約](docs/acceptance.md#生成内容と正答の必須テスト)に従い、テスト未整備・失敗のまま配布しません。

## GitHub Pages

静的ビルドとハッシュ形式の画面遷移を使い、リポジトリのサブディレクトリから配信できます。バックエンド、認証、課金はありません。

GitHubへ配置した後、Settings → Pages → Sourceで **GitHub Actions** を選び、Actions → **Deploy OpenCBT to GitHub Pages** → **Run workflow** を実行します。[ワークフロー](.github/workflows/pages.yml)は手動起動のみで、test・build成功後にdistを配信します。リポジトリのpublish／pushと、Pagesでのアプリ配信は別の操作です。pushだけではPagesへデプロイしません。
