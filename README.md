# OpenCBT-FE-KihonJoho

基本情報技術者試験（FE）の学習とCBT形式の操作練習を行う、非公式のフロントエンドアプリです。IPA・プロメトリック・試験運営事業者とは関係ありません。

**公開アプリ：[OpenCBT FEを開く](https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/)**

公開情報をもとにCBTの画面・操作を再現しています。実際の試験画面・動作とは異なる場合があります。解答・復習画面のフッターには出典、改変区分と必要な権利文言を表示し、展開すると素材別の条件や改変概要を読めます。「出典・改変詳細」と「ライセンス表記」は展開部分から同じ画面で開いて閉じられます。

2023〜2026年度のIPA公開問題103問と、それらの画像・記述を基に作図・バインド・正答生成を行う103種類の改変テンプレートを収録しています。2025年度科目B問6はJIS文言の利用条件未確認のため除外しています。公開問題は本番の全問題ではありません。原問題の詳細解説は未収録です。

## 起動

Node.js 22.x又は24.xとnpmを使います。検証環境はNode.js 24.10.0／npm 11.6.0です。

```sh
npm ci
npm run dev    # アプリ。既定 http://127.0.0.1:5175/
npm run doc    # 仕様書。既定 http://127.0.0.1:5173/
```

別々のターミナルで起動します。両方ともループバックで待ち受け、ポート使用中は空きポートと実際の閲覧URLをログに表示します。停止はCtrl+Cです。

年度別オリジナルとランダムミックスを選べます。年度別は原文・元の数値を維持します。ミックスは分野構成を保ち、全問の本文・図・選択肢・正答・解説をパラメータから生成します。固定問題の並べ替えと独自学習問題の選択肢は廃止しました。選択肢の行を押して解答します。丸いラジオボタンと右端のチェックは表示せず、選択肢の本文・図表の表示幅を確保します。選択中は太い枠と背景で示します。選択済みの行を再選択すると解除でき、解答欄下部の旗アイコンで見直しを切り替えられます。ヘッダーは二段構成で、上段にロゴ・科目／モード・練習名とブックマーク・一時停止・正答表示・問題一覧、下段の左に資料一覧・手ボタン・＋／−・ズーム選択を、右に時計・終了操作を置きます。資料一覧からページを選び、手ボタンで本文・図表をドラッグしてスクロールできます。ズームは左の問題資料へ適用し、自動・実際のサイズ・ページに合わせる・幅に合わせる・50〜400％を選べます。本文・図表は問題資料に一度だけ表示し、解答領域には問題番号と選択肢をまとめます。復習や狭い画面でも重複表示しません。時間付き練習は中断中も期限が進み、終了後に学習正答率を表示します。公式IRT評価点・合否は算出しません。

サイドバー下部（狭い画面ではフッタ）の太陽・月でライト／ダークモードを切り替えられます。両モードとも白・黒・グレーを基本色とし、正誤・注意・エラーなど意味を伝える色は保持します。表示設定はこのブラウザに保存し、再読み込み後も保持します。

生成問題は原問題の出力形式を崩さずに抽象化します。問いの方向、正誤条件、解答対象、選択肢の役割と数を固定し、対象・条件・値を同じ役割の位置へ埋め込みます。例えば「クイックソートの処理方法を説明したものはどれか。」は、ソートの対象を変えても処理方法の説明を選ぶ問いを維持します。文章は文章へ、箇条書きは箇条書きへ値を埋め込み、元からある表・図・空欄付き疑似言語を保持します。解法の補助表や図の接続説明は出題本文へ追加しません。アローダイアグラムの円・上下ラベル・破線・凡例、文章図の見出し・箇条書きを維持し、代替説明は読み上げ用に保持します。保存済みアローダイアグラムにも表示互換を適用し、数値・正答を変えません。全103系列の問い方と注意書きを原資料と照合し、記号の定義・前提・入力域・添字・未定義要素・単位・端数処理・繰返しの非実行条件も解答前の本文・図表へ保持します。条件を変えた場合は関連する注記も同時に更新します。新規開始には既存13系列の生成器2.1.0、追加90系列の3.2.0を使います。今回の未公開段階の更新には旧版の後方互換を設けません。正答の一意性に問題があった旧4系列は取り下げ通知の対象とし、その旧版を含む保存記録は更新確認時に削除します。

ミックスは収録済み103問すべて（科目A80・科目B23）の登録テンプレートに対応しています。数値・引数・図の条件に加え、知識問題では原問題の問い方・判定条件を保ったまま対象や状況を変え、選択肢・正答・独自解説を一緒に生成します。生成版は改変問題であり、公式原文の再録とは区別します。[問題別の対応一覧](docs/generation-coverage.md)は配布データと登録契約から生成・検証します。同じテンプレートの異なる入力を出題できます。直前に保存した同テンプレートのセッションで使った入力を避け、正答を変えられる問題では直前の正答値も避け、選択肢順を抽選します。四つの産業財産権のように正答が固定された問いは、その列挙形式を保ち、誤答候補の権利を変えて生成します。原問題とバインド前の完全な基準問題を保存し、全生成問題を改変ありと記録します。再開・復習で再生成しません。解答・結果は端末内のIndexedDBに保存し、最終更新から180日で削除します。履歴で1件／全件削除できます。

解答・復習画面のヘッダーにあるブックマークボタンで、繰り返し練習したい問題を保存できます。結果画面では未解答と不正解の問題をそれぞれまとめて追加できます。一覧には元問題の文頭と、ストラテジなどの分野名を表示します。メニュー左列の「ブックマーク」から問題を開くと類題を生成し、「次の類題」で条件を変えた問題を連続して解けます。各問の解答・結果は履歴へ保存し、再開・復習では生成済みの内容を使います。ブックマークは履歴と別に保存し、履歴削除や180日の期限では削除しません。ブックマークの削除又はサイトの保存領域の消去で削除できます。利用できなくなった原問題の参照は更新確認時に削除します。

## 検証・ビルド

```sh
npm run test           # 出題・生成・期限・正答・不正データ
npm run data:validate  # 本体配布データ・参照・画像・権利記録
npm run build          # 検証・型確認後、distへ静的ビルド
npm run preview        # distを127.0.0.1:4175で確認
npm run doc:build      # 文書・Schema・35サンプル・51不正例の検証とビルド
npm run doc:reference  # Schema変更後のフィールド辞書再生成
npm run doc:generation # 配布データと登録契約から生成対応一覧を更新
npm run check          # 本体テスト・ビルド・文書ビルドをまとめて実行
```

## 開発規約

[AGENTS.md](AGENTS.md)と、リポジトリ内の[FE問題の全件生成対応スキル](.agents/skills/fe-question-generation/SKILL.md)に従います。対象範囲内で用意可能な問題の全件対応を完了条件とし、配布検証で維持します。メニューへ対応件数やバインド方式の説明欄を追加する運用は行いません。

問題や生成器の追加・変更では、計算・アルゴリズムを独立した参照解法で照合し、知識選択を査読済みの対応資料で検証する自動テストを必須とします。全選択肢の成立条件、正答の一意性、本文・図・解説との整合を確認します。[必須テストの規約](docs/acceptance.md#生成内容と正答の必須テスト)に従い、テスト未整備・失敗のまま配布しません。

## GitHub Pages

静的ビルドとハッシュ形式の画面遷移を使い、リポジトリのサブディレクトリから配信できます。バックエンド、認証、課金はありません。

公開先は [https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/](https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/) です。**mainへのpushで自動デプロイ**します。[ワークフロー](.github/workflows/pages.yml)がNode.js 24で依存を導入し、test・配布検証・型確認・buildが成功した後にdistを配信します。実行結果は[GitHub Actions](https://github.com/Masashi-desu/OpenCBT-FE-KihonJoho/actions/workflows/pages.yml)で確認できます。

GitHub側の初期設定はSettings → Pages → Sourceの **GitHub Actions** です。再デプロイする場合はActions → **Deploy OpenCBT to GitHub Pages** → **Run workflow**でmainを選びます。main以外のブランチでは配信しません。`npm run build`はローカルの静的ビルドです。

## 仕様・出典・利用条件

OpenGraph画像、共有メタ情報、Web App Manifest、ロゴ・ファビコンは`npm run assets:generate`でまとめて生成し、`npm run assets:check`で正本との一致を確認します。文字・配置・配色・公開URLの正本は`scripts/brand/site.json`です。[共有資産の管理](docs/sharing-assets.md)を参照してください。dev・buildでは自動再生成し、test前に鮮度を検査します。生成用フォントはリポジトリへ同梱せず、初回にCDNから固定版を取得してhashを検査し、`.cache/brand-fonts/`へ保存します。`npm run fonts:prepare`で事前取得でき、以後はキャッシュを再利用します。閲覧時のフォント通信は追加しません。

ロゴとファビコンは`npm run icons:generate`で再生成できます。資格コード、色、文字の位置・寸法、フォント、出力先を指定できます。[生成方法](docs/brand-icons.md)を参照してください。

[仕様の入口](docs/index.md)、[実装と収録範囲](docs/implementation.md)、[参照資料](docs/references.md)、[公開前査読](docs/review.md)、[検証記録](docs/verification.md)、[起動・編集方法](docs/contributing.md)を参照してください。Schemaと説明用サンプルはdocs/public、本体配布データはpublic/dataに分離しています。

独自コード・文書は[MIT](LICENSE)、独立作成の問題・解説・図データはCC0-1.0です。IPA問題・正答・画像と依存ライブラリには個別の条件を適用し、MITを自動適用しません。[NOTICE](NOTICE.md)とメニューの「ライセンス表記」で全文と範囲を確認できます。ロゴは独自のベクタ、その他のUIアイコンはLucide、数式は固定版KaTeXをSRI付きでCDNから取得します。学習記録を外部送信しませんが、数式資産の取得時にCDNへIPアドレス等が届きます。
