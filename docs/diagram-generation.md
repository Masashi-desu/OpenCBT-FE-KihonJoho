# 図描画・問題生成・改変表示

## 採用する方式

本システムでは、公開原問題の画像・本文を基に、開発側で図の構造、変数、入力間の条件、正答計算、解説を定義する。ランダムミックスはこの登録テンプレートへ毎回新しい値をバインドし、全問の本文・図・選択肢・正答・解説を生成する。固定問題の順序だけを変えた出題や、別の独自学習セットは採用しない。年度別オリジナルは原文・図・元の数値・選択肢順を維持する。

図の表示はsrc/ui/Content.tsxとsrc/ui/SourceFigure.tsxの管理されたHTML・CSS・JavaScriptと、同コードが構築するSVGで行う。JSONへHTML、CSS、JavaScript、外部スクリプトURLや汎用計算式を入れない。表示する疑似言語は説明用であり、ブラウザで評価・実行しない。正答は登録されたTypeScriptの生成器が計算する。

### 原問題の出題形式の維持

[問題作成・可変問題の品質規約](/question-authoring)を作問・既存系列の修正・公開問題追加へ適用する。このページは現在の生成・描画の実装を説明し、品質判定の共通規則は同規約、合否に必要な検証は[受入条件](/acceptance)へ対応付ける。

全ての改変問題は、原問題の出力形式を崩さずに抽象化する。問いの方向、肯定・否定及び正誤の判定条件、解答対象、選択肢の役割と数を固定する。処理方法の説明を選ぶ問いでは、可変対象に対応する説明を選択肢として生成する。

原問題が文章ならparagraph、箇条書きならlist、表ならtable、図ならdiagram又は文章図、数式ならformula、疑似言語ならcodeで生成する。数値・名称・条件は、原資料の中で同じ役割を持つ位置へバインドする。元からある図・表・数式・空欄・解答群を維持し、解法の補助図・補助表・途中式は正答表示後の解説に置く。図の代替説明はaria-label又はSVGのdescに保持する。

原資料の文章を枠で囲った図はcontexts[].presentation=text_figureとし、HTMLのfigureで表示する。見出しの階層と項目の区分を保ち、図題と素材の出典は本文の枠の外へ置く。省略又はtextは通常の参照本文とする。この指定からスクリプトを実行せず、任意HTMLを受け取らない。

生成器は本文ブロックの種類・順序、選択肢数・種類、文章図の構成をvalidateSourceFormatで検査する。原資料と照合した記号の定義、前提、入力域、添字、未定義要素、単位、端数処理、疑似言語の非実行条件を解答前の本文・図表に表示する。基準値・異なる入力・境界の表示と通常のデータ・参照検証を併用する。基準問題・テンプレート・セット・試験設定の現行改訂は配布カタログ、生成器の版は[生成対応一覧](/generation-coverage)で確認する。非互換の履歴や訂正は[保守方針](/maintenance)に従う。

## 原画像から作図・バインド・正答ロジックを定義する工程

1. sourceRefsとlocatorで公開原資料・ページ・問番号を特定し、rightsから表示・改変・再配布・第三者素材の条件を確認する。
2. 元画像と抽出文字情報を照合し、図のノード、矢印の向き、接続、ダミー作業、表の行列、添字、単位、丸め規則を読み取る。画像の見た目だけから数値の役割を推測しない。
3. 元の問題をofficial_reprintの不変questionとして保持する。生成用にはofficial_adaptationの基準questionを別に作り、原問題へのderivedFromと出典を維持する。基準値の完全な本文・図・選択肢・正答・解説を保存する。
4. templateに基準questionのID・改訂・内容hash、generatorRef、referenceParameters、位置別の入力域、素材の出典・条件を記録する。登録生成器へ作図、バインド、正答・誤答・解説の計算を実装する。
5. 元の数値・構造で照合し、境界・条件違反・異なるシードを検査する。生成器とは別の計算方法で正答を確認し、図の値と計算値を照合する。
6. 配布カタログとgenerationBindingsへ組み入れる。未対応の画像をOCRで自動変数化したり、画像だけを取得して未知の正答を推測する処理は提供しない。

描画し直すことは出典や元の図への依存を消すことではない。問題・図・選択肢は改変元の条件と本プロジェクトの作成部分を部品別に維持する。生成した正答・解説は本プロジェクトの独自計算・記述であり、公式作成と表示しない。

## 管理された描画器

renderer-diagram-basic@1.0.0は宣言的sceneだけを受け取る。arrayはセルの添字・値、graphは頂点と有向／無向の辺、flowchartはstart・end・process・decisionの形状と接続を持つ。ノードID・辺IDは図内で一意、辺のfrom・toは同じsceneのノードを指す。ノードは最大50、辺は最大100、座標は0〜1000の有限整数とする。表示するラベル・altは文字列として扱いHTMLを解釈しない。

graphのroleはvertexとする。図中に存在しない内部IDや節点名を表示しない。専用の描画器を使う場合は、受理する構造・値域・接続・図の読み方を登録契約に定め、不一致を拒否する。

節点や線種、矢印の方向、ラベルの位置、凡例など、読取りに必要な原図の構成を保つ。分岐や戻り線は処理枠・ラベルから離し、接続先を読めるようにする。図が収まらない場合は図の領域内でスクロールし、文字拡大でも図形とラベルの対応を維持する。スクロール領域にはキーボードからフォーカスできるようにする。図形の重なりや領域外への描画で表示できない場合は、拡大を戻して再表示できるよう案内する。

既存の保存図に表示互換を適用する場合は、登録した構造と一致する図に限定する。入力・接続・正答・解説・hashを保持し、表示に必要な描画だけを変える。描画器固有の形状・配置・寸法と照合方法は個別仕様に記録する。

## 登録生成器と基準値

ランダムミックスは、収録した原問題・大問に一対一で対応する現行の登録生成器を使用する。[生成対応一覧](/generation-coverage)で原資料・生成器版・入力域・表示形式を確認する。基準値とフィールドの正本は配布カタログが参照するテンプレート、生成方法と入力間の制約は登録された生成器と抽選器とする。本文・図・表・選択肢・正答・解説は同じ入力から作る。画面の選択肢記号とchoiceIdを分けて保存する。

原問題に固定入力のない動作確認例や、生成で追加したオフセット・可変幅は改変内容へ記録する。計算問題の桁数・丸め・選択肢間隔は[作問品質規約](/question-authoring#qa-03-—-計算精度と負担を原問題へ合わせる)に従って系列ごとに定め、根拠・許容精度・相関条件・独立検算を査読記録とテストへ対応付ける。

数式の表示準備は[本文形式](/content-format)に従う。開始前に実際に出題する式の組版を確認し、準備完了後に解答時間を開始する。

## 元データと出題経路

バインド前の元データは完全な基準questionとして保持する。原問題の公式再録も同じsnapshotに含め、基準問題のderivedFromから追跡できる。テンプレートのoriginalContentSha256はこの基準questionを固定する値であり、原画像との差を測る値ではない。

| セット | session.bindingMode | 出題内容・保存 |
| --- | --- | --- |
| 年度別オリジナル | original_data | 原問題をそのまま表示。bindingPerformed=false、instanceなし、作成時の改変表示を維持 |
| ランダムミックス | generated_values | 全枠の値・図・選択肢・正答・解説を生成。bindingPerformed=true、isModified=true、instanceを保存 |

ミックスで元データ使用を選ぶUIは設けない。生成不能の枠を固定画像の問題で補充しない。交換形式のoriginal_dataは過去の説明用サンプルや保存状態でも有効だが、現在のミックスの新規開始には使用しない。

## シード・入力抽選・重複回避

開始時にCrypto APIで128bitのシードを抽選し、32桁の小文字16進文字列として保存する。SHA-256へ渡すUTF-8文字列はseed、template.id、revision、generatorRef.id、generatorRef.version、counterをLFで結合し、末尾LFなしとする。

登録生成器の抽選ではdigestを先頭から8桁ずつ読み、符号なし32bit整数にする。各fieldの幅wに対しfloor(2の32乗÷w)×w以上を捨て、minimum+(整数mod w)へ対応させる。counterは0から始まる10進整数で、8整数を使い切ったら次のdigestへ進む。抽選1値につき最大1024試行、入力間の条件を満たす列の選択は最大256列とする。

入力間の関係、計算結果の成立条件、選択肢の一意性を登録契約に照らして検査する。違反した候補は出題せず、定義した限度内で次の候補を選ぶ。

問題数が決まるミックスでは、同一セッションの同じtemplate ID・revisionの同じ入力を重複させず、端末に残る同テンプレートの直前セッションの入力も避ける。無限周回と個別・全件のブックマーク練習はrandom_reuseを使い、同系列の直前の入力を避けながら過去の条件を再利用できる。有限の候補でも継続でき、出題済み内容と回答は保持する。旧instance_uniqueの個別ブックマーク練習は次問追加時に設定の不変参照を新設し、既存問題を変えずにrandom_reuseへ移行する。

抽選器が生成した有効な入力は、基準問題と同じ入力・正答でも候補に含める。基準値であることを理由に恒久的に除外しない。正答を変えられる問いでは同テンプレートの直前の生成正答だけを避け、選択肢順を別途抽選する。この再抽選は1枠128回までとし、枠を確保できなければ開始を止める。履歴削除・別端末・同時開始をまたぐ永久的な非重複や、有限回の抽選ですべての候補が必ず現れることを保証する機能ではない。これらの比較は出題候補の選択であり、isModifiedの判定には使わない。候補選択の変更で生成器の入力域・版・シード再現契約・保存済みの出題内容を変更しない。

各fieldの最小・最大は保存値を検証する範囲であり、計算問題の抽選候補にはさらに系列別の刻み・列挙候補・相関条件を適用する。基準値に適用する条件と新規抽選の制約が異なる場合は、その理由と境界を記録する。抽選制約はsampleCalculationInputsと登録契約、検証は問題集別の内容・抽選テストで確認する。

同じtemplate・生成器の版・seedから同じ入力、同じ入力から同じ表示内容を得る。採用したseed・入力・instance全体を保存し、棄却した候補を採点しない。再開・復習・結果では再生成しない。現在のミックスは同系列の別入力を許可するinstance_unique、年度別は系列重複を許さないlineage_uniqueとする。同じ系列が複数あることを異なる知識の網羅数と表示しない。

## 保存・検証・例外

元データsnapshotを保存してからバインドする。生成結果・instance・sessionの検証と保存を完了してreadyへ移り、running開始から制限時間を測る。登録外の生成器、入力域不一致、参照切れ、正答の不一致、表示準備・保存失敗では開始を止め、再試行・選び直し・ライセンス一覧へ進める。

instanceは所有sessionId・entryIndex、templateRef、baseQuestionRef、generatorRef、seed、parameters、question、contentSha256、bindingPerformedを持つ。sessionのquestionRefは基準問題、表示と採点はその枠のinstance.questionを使う。表示ラベルと正答の対応はsession.entries[].choiceOrderに固定する。

IndexedDBのcatalogSnapshots・generatedInstances・sessions・resultsを同じ保存単位で扱う。180日保持、1件／全件削除、孤立データの削除、訂正・撤回は[保守](/maintenance)に従う。原資料又は基準問題を撤回する場合、派生するinstanceと元データも削除対象とする。

## 改変表示とhash

固定questionのorigin.isModifiedは作成時の原本照合で記載する。バインドした枠は出題経路に基づきtrueを保存する。元の値と一致する生成を交換形式で記録する場合も改変ありであり、値の大小・文字差分・画像hash・changesの件数から改変有無を逆算しない。changesに編集主体・対象・説明を記録し、正答を明かす内容はanswerDetailsへ分ける。

S09で元データ、出典、原問題へのリンク、変更内容、生成器・シード・入力を確認できる。基準問題の正答・解説・answerDetailsは終了後又はstudyの正答表示後に限る。結果・一覧・復習でも改変表示を維持する。[表示対応](/attribution)を参照する。

contentSha256はquestion全体をsorted-json-v1で固定する。オブジェクトのキーをUTF-16コード単位順に再帰的に並べ、配列順を保ち、JSON.stringifyの空白なし表現をUTF-8にしてSHA-256を計算する。文字列をUnicode正規化しない。catalog.filesのhashは元ファイルのバイト列であり、計算対象が異なる。いずれも保存・取得の一致検査であり、著作権上の改変検出・正答の証明・発行者の真正性・不正防止には使用しない。

## 説明用の既存配列サンプルと検証の限界

文書のarray-sum@1.0.0は交換形式の説明用サンプルとして保持する。3要素・1〜9・基準[3,5,2]を足し、総和と±1・+3の選択肢を作る。旧シード契約はdigestの各バイトを252未満で採用し、byte mod 9+1、最大16digestとする。本体の新規出題候補には含めない。既存の保存記録は当時の問題として復習可能とする。

本体テストでは基準値・境界・再現可能なシードに対する表示と正答、図の接続・値、正答の一意性、元データの保持、全枠生成、重複回避、保存内容を検査する。小さい入力域では有効な組合せを全列挙する。独立解法又は査読済みの知識資料と照合する。[サンプル](/samples)・[受入条件](/acceptance)・[実行記録](/verification)を参照する。

## 登録図と契約の更新

原問題ごとの生成処理と入力域は管理済みの生成器として登録し、問題データからはIDと版で参照する。知識問題は原問題の問いの方向と判定条件を保ち、数値・プログラム・長文は対象に応じた構造と正答計算を定義する。ランタイムでデータ中の式や任意コードを評価しない。

renderer-source-figures@1.0.0はsource_figureを受け取り、profileとvaluesから登録済みの形状を描画する。[位置別の値域](/generation-coverage#登録図の入力契約)に一致しない入力はFIGURE_PROFILEで拒否し、別種のsceneをこの描画器へ渡さない。図IDは選択肢を含めて問題内で一意とする。

問題・生成器・描画器の改訂と保存互換は[保守方針](/maintenance)に従い、現行の契約と発行時の出題内容を区別する。
