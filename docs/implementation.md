# 実装・収録データ・配信

## 現在の成果物

2026年10月6日の明示的な実装開始指示を受け、OpenCBT-FE-KihonJohoのフロントエンドを実装した。npm run devで本体、npm run docで仕様書を起動する。静的ファイルだけで動作し、アカウント・API・課金・解析サービスを持たない。2026年10月7日の公開指示に基づき、mainへのpushでアプリをGitHub Pagesへ自動配信する。

Lucideを操作アイコンに使用する。プロメトリックの公開汎用画面は資料・解答・操作領域の関係を参照したが、配色・文言・アイコン・コードは独自に作成した。担当分離のあるクリーンルームを実施したとは称さない。現在のFE本番画面を保証する資料とも扱わない。

## 収録範囲

| 公開年度 | 科目A | 科目B | 根拠・除外 |
| --- | --- | --- | --- |

| 2024 | 20問 | 6問 | 同上 |

| 2026 | 20問 | 6問 | IPA問題PDFと解答例 |

合計206件の問題定義、うち公式再録103問と改変済み基準問題103件。登録テンプレートも103件を持つ。問題画像118ファイルをWebPで配布し、年度別オリジナルで使用する。生成版の図は画像を加工して表示するのではなく、元画像から定義したノード・接続・表・計算規則へ値をバインドして描画する。公式PDFそのものや汎用画面の画像は同梱しない。public/data/catalog.jsonの許可リストに収録した資源だけを出題候補にする。除外問題の本文・画像・正答は同梱しない。文書用の35レコードとは別の配布カタログである。

原文の組版、図表、解答群を保持するため、公式問題はPDFから問題部分を切り出した原文画像を中心に表示する。選択肢IDと原文のア〜コを対応させ、公式問題の選択肢は並べ替えない。年度別は元の問番号順・元の数値を維持する。

解答・復習画面では、共通本文・注意書き・問題文・図表を問題資料に一度だけ表示する。解答領域は問題番号と選択肢・解説を表示し、同じ問題文や図を繰り返さない。年度別・ミックス・ブックマークからの生成練習に共通で適用し、狭い画面ではこの構成を縦に並べる。保存済みの問題内容・正答は変更しない。

下段ヘッダーの左には、資料のページ一覧・手ボタン・＋／−・ズーム選択を並べる。MaterialViewerが表示中の資料を原文画像又は本文・図表の単位へ分け、同じ順序で描画する。ズームとドラッグは左の資料へ適用し、スクロールする図表から本文へ移動量を渡す。一覧・倍率・手ボタンの状態は表示用に保持し、セッションの問題・解答・保存形式を変更しない。

画像の補助としてPDFの文字情報を表示するが、図の接続、空欄、表の読み順をすべて意味構造へ変換したものではない。画像依存の問題には読み上げの限界がある。キーボードで選択・移動できることと、全問題のアクセシブルな意味表現が完成していることを混同しない。

年度別オリジナルの詳細解説は収録していない。終了・復習で公式正答と「詳細な独自解説は未収録」と表示する。生成問題の解説は本プロジェクトが同じ入力・計算結果から作成する。第三者教材の解説をIPAの条件で取り込まない。原文照合と正答表の確認を同じAIエージェントが実施し、人の二重照合を行ったとは表現しない。

## 出題と生成

年度別オリジナルとランダムミックスを選べる。ミックスは固定問題の並べ替えではなく、問題内の要素を変数とした生成出題である。別の独自学習セットは廃止する。「傾向」は[分野別件数](/sessions#ランダムミックスの分野構成)として具体化し、非公開本番の難易度や小分類を推定しない。

Aは20問又は60問、Bは6問又は20問を、登録テンプレートから生成する。同じ系列の異なる入力を許可し、全枠を生成して各枠を採点する。これを60種類の異なる知識・原問題を網羅したとは表示しない。必要分野に生成器がない場合や、一意な入力と、問いに対して一意な正答を作れない場合は開始を止め、固定問題や独自の補充へ無断で代替しない。

収録103問すべてをミックス候補とする。科目Aでは数値・構造・図に加え、知識問題の問いの方向・判定条件・選択肢の役割を固定し、用語・問う対象・状況を変更する。科目Bでは疑似言語の空欄・引数・添字・配列・図・長文の規則や状況を変更する。[全問題の対応と入力域](/generation-coverage)を正本から生成する。選択肢順だけで生成対応と扱わない。生成用基準問題は明示条件や文言を含む改変版であり、公式原文そのものと表示しない。

原問題と完全な基準questionを先にsnapshotへ保存し、bindingMode、bindingPerformed、isModified、シード、入力、生成済み内容を保存する。年度別はoriginal_data、ミックスはgenerated_valuesで全問改変あり。改変表示は出題経路から保持し、再開時に再抽選・差分判定しない。以前の固定ミックス・独自セットの履歴は削除せず、当時の内容を維持して変更前の方式と表示する。

## 履歴の絞り込み

履歴は保存されたselection.kindで年度別問題・ランダムミックス・ブックマーク練習を絞り込む。初期表示は「すべて」で、同じ画面内で結果や復習から戻った場合は選択中の種類を保持する。種類に該当する履歴がない場合は、空表示から「すべて」へ戻せる。絞り込みは表示だけへ適用し、保存済みの問題・解答・結果や並び順を変更しない。個別削除は表示中の項目を対象とし、「すべて削除」は絞り込みに関係なく全履歴を対象とする。

## 選択欄のブラウザ互換表示

年度・各画面の絞り込み・資料ズームのHTML selectに共通の外観を適用する。WebKitの標準描画による余白・高さの上書きをappearanceで解除し、テーマの文字色を使うCSSの矢印と右余白を設ける。通常欄は42px、一覧の絞り込みは35px、資料ズームは30pxの高さを保つ。選択肢、値の更新、キーボード操作は既存のselectを維持する。学習モードは学習・復習／時間付き練習／無限周回、ミックスの出題数は短い練習／本番の問数のセグメントを使う。無限周回では年度・出題数を省略し、科目の全生成系列から毎回独立にランダム抽選し、共通追加処理で1問ずつ追加する。

## ブックマークと連続練習

解答・復習画面のヘッダーの「学習・操作補助」領域にブックマーク操作を置く。年度別オリジナルとその生成問題は、同じ原問題の参照で一件にまとめる。結果画面では正答表示の集計上の注意をカードの最上部へ置き、未解答・不正解の一括追加を集計の下に中央寄せで配置する。その下は履歴・メニューへの戻る操作を左、続けて練習・復習を右へ置く。540px以下の画面では練習・復習を上段、戻る操作を下段へ並べる。一括追加は保存された結果の判定とセッションの元問題参照で対象を選び、利用できない原問題を除外し、同じ原問題と追加済みの項目を重複させない。一つの保存トランザクションで追加し、既存の保存日時を保持する。対象がない場合や対象をすべて追加済みの場合はボタンを無効にする。メニュー左列の「ブックマーク」には科目・年度・問番号、元問題の文頭と分野名のラベルを表示し、個別削除と「類題を練習」を用意する。

一覧の上に操作コンテナを置き、右端の「すべてのブックマークの類題を練習」で全登録問題の無限周回を開始する。空一覧・読込み中・保存中は開始できない。開始時の参照を固定し、科目A・Bを含めた全候補から毎回ランダムに問題定義を選んで類題を生成する。同じ系列の連続出題も許可する。任意の問題群を扱うselectEndlessQuestionsを通常の無限周回と共用し、set.questionRefsと生成対応を保存する。開始後のブックマーク追加・削除では保存した候補を変更しない。個別に開くと、その問題に対応する登録テンプレートから時間制限なしの問題を一問生成する。「次の類題」は同じ練習の末尾へ新しい問題を追加し、既存の解答を保持する。直前の入力を避け、正答を変えられる問題では直前の正答も避ける。終了結果からも保存した問題群の練習を続けられる。全問を一つのセッションへ保存・集計し、再開・復習時には生成済みの内容・正答・選択肢順を維持する。出典・改変・素材別権利表示は通常の生成問題と同じ条件で行う。

ブックマークには原問題の参照と一覧用の情報を保存し、問題本文や正答は複製しない。一覧の文頭は配布カタログの原問題から取得するため、追加前に保存したブックマークにも表示する。科目Aは最初の一文、科目Bは処理や状況の説明を含む冒頭最大140文字を表示し、長い本文には省略記号を付ける。IndexedDBの保存識別子は維持し、版3でbookmarks保存先を追加する。履歴削除・180日保持とは独立し、個別削除又はサイトの保存領域の消去まで保持する。配布カタログから利用できなくなった原問題の参照は更新確認時に削除する。ブックマークの保存失敗はその操作だけのエラーとして通知し、未保存を保存済みと表示しない。

## GitHub Pages

本体は相対資産URLと#/exam等のハッシュ経路を使う。リポジトリ配下のURLから起動・再読み込みしても、GitHub PagesにSPAのサーバルーティングを要求しない。

公開先は[OpenCBT FE](https://masashi-desu.github.io/OpenCBT-FE-KihonJoho/)。配信手順は次のとおり。

1. 初期設定としてSettings → Pages → SourceでGitHub Actionsを選ぶ。
2. mainへpushするとDeploy OpenCBT to GitHub Pagesが自動起動する。
3. テスト・配布検証・型確認・ビルド成功後、distをPages artifactとして配信する。
4. [Actionsの実行結果](https://github.com/Masashi-desu/OpenCBT-FE-KihonJoho/actions/workflows/pages.yml)と公開URLを確認する。

再デプロイにはActions → Deploy OpenCBT to GitHub Pages → Run workflowでmainを選ぶ。main以外では手動起動しても配信しない。同時配信を防ぐためconcurrency groupをpagesに固定する。npm run buildはローカル生成だけを行う。GitHub側の権限・Pages設定・実際の配信URLは、ローカル配信の確認だけでは検証済みとしない。[R23](/references#r23--github-pages)を参照する。

旧4系列の基準問題改訂2はanswer_correctionで通知する。旧版を含むsnapshot・セッション・結果・生成済み問題は更新確認時に削除し、黙って再採点しない。[修正内容と査読の限界](/review)を参照する。

## 図の出題形式の維持

アローダイアグラムは専用の登録描画器で、円形の無記名節点・矢印・上下の作業名と所要日数・ダミー作業の破線・図内の凡例を保持する。原図にない接続説明、補助表、節点名、0日のラベルを通常画面へ追加しない。代替説明はSVGのtitle／descに保持する。既存保存図にも表示互換を適用し、保存済み入力・正答を変えない。ログ管理の文章図は番号付きの5見出しと箇条書きを保持する。詳細は[図描画](/diagram-generation#管理された描画器)を参照する。
