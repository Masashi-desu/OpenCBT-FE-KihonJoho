# 問13のアローダイアグラム解説

## 初期条件と原問題の照合

2024年度科目A問13の通常解説・検索・復習から開く、HTML/CSS/JavaScriptの問題専用コンポーネント。配置はpublic/explanations/ipa-2024-a-13/、共通の[詳細解説ホスト](/detailed-explanations)で隔離実行する。初期値は収録済み原問題と同じA=30、B=5、C=30、D=20、E=40、F=25、G=30、H=30日。上側→中央、中央→下側のダミーは0日で、両方を有効にする。

元問題の最短完了は120日（ウ）。最早時刻は開始0、分岐30、上側35、中央60、下側60、合流90、終了120日。クリティカルパスはA→C→ダミー（中央→下側）→G→H。ダミーを省いた作業名だけの表記ではA→C→G→Hとなる。

原冊子・公式解答・公開問題の利用条件を2026-10-14に再確認した。[問題冊子の6ページ](https://www.ipa.go.jp/shiken/mondai-kaiotu/sg_fe/koukai/eid2eo0000007g1d-att/2024r06_fe_kamoku_a_qs.pdf#page=6)、[解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/sg_fe/koukai/eid2eo0000007g1d-att/2024r06_fe_kamoku_a_ans.pdf)と収録画像を照合している。図の接続構成はIPA原図に基づく改変としてmanifestに記録し、rights-ipa-2024-aとrights-originalを分けて継承する。操作UI・計算説明・コードは独自作成。原問題の本文、全選択肢、正答は保持する。

## 図上の操作

問題専用のタイトル・最短完了日数・条件説明のヘッダーと、独立した凡例・再生フッターを設けない。表示切替と拡大縮小は図の面へ配置し、「計算をたどる」を図の左下、「初期値に戻す」を右下へ置く。完了時刻は終了地点、選択内容、読み上げ通知で確認する。元問題の出典・ライセンス・改変情報は詳細解説画面で常時展開し、折り畳み操作を表示しない。

単一の図の表示領域で、実線の作業、円の結合点、破線のダミーを選択する。図の下にPCでは高さ280px、600px以下では320pxの予約領域を初期表示から確保し、見出し・計算式・編集操作・時刻をその領域の幅全体へ直接配置する。独立したカードの枠・影・中央寄せの幅制限・接続用の点線を設けない。PCでは日数入力と時刻を横に並べ、狭い画面では縦に並べる。選択前と閉じた後には操作案内を表示する。内容が多い場合は表示領域をスクロールし、領域の高さは変えない。図と説明を左右の別ペインへ分離せず、図を横スクロール・拡大できる。スクロールバー・色・フォントは本体の正本を使う。

- 条件のドロップダウンは設けず、図上の選択から編集する。作業の矢印・作業名・日数から直接選択し、結合点の計算表示に作業やダミー設定への遷移ボタンを設けない。作業A〜Hは現在値を入れた数値入力から編集する。「適用」又はEnterで確定し、閉じても値を保持する。0以上の整数を受理し、空欄、負数、小数、指数表記、不正文字を拒否する。入力が不正なら計算状態を変えず、入力欄の近くにエラーを表示する。
- 作業の所要日数、最早・最遅の開始と終了、トータルフロート、最早と最遅の時間帯を表示する。各作業が余裕を同時に独立して使えるという説明にはしない。
- 結合点では先行作業の到達時刻と最大値の式を表示する。計算項目を選択すると対応する矢印を強調する。関係のない矢印は薄くする。
- ダミーは0日の依存関係と説明し、2本を個別に有効・無効へ変更する。無効な破線は残して状態を示し、計算対象から除く。
- クリティカルパス、最早時刻、ダミーの強調を切り替える。クリティカルパスが複数ならダミーを含む全経路を表示する。図上の経路と作業選択の説明が対応する。
- 最初、前へ、次へ、自動再生、一時停止で9段階を追う。先行地点を計算してから接続先へ進み、E・F・Gの到達比較と合流の最大値を分け、最後にクリティカルパスを示す。日数や依存関係を変えると再生を停止し、計算過程を再生成する。
- 矢印・円はEnterとSpaceで選択できる。選択中の同じ対象をクリック・タップ又はキーボードで再選択すると解除し、表示領域を操作案内へ戻す。確定した日数とダミーの有効・無効を保持し、再生中なら停止する。編集欄へフォーカスを移し、Escape又は閉じるで選択元へ戻す。入力と主要ボタンは44px以上の高さを確保する。
- 選択、編集、補足の展開、開閉で図の高さや「計算をたどる」の位置を変えない。クリティカルパス一覧は図の下の予約領域へまとめ、ステップの状態表示は図内の再生操作と併記する。

## 計算と保存互換

arrow-engine.jsは有効な矢印だけでトポロジカル順序を作り、最早時刻を前向きの最大値、最遅時刻を後ろ向きの最小値で計算する。余裕時間は最遅終了−最早開始−所要日数。余裕0日の矢印を開始から終了へつなぎ、全クリティカルパスを求める。整数はBigIntで計算し、浮動小数点の精度不足による丸めを起こさない。長い日数は図のラベルを省略表示し、選択時と読み上げには完全な値を使う。矢印の長さ自体は日数を表さない。

生成問題ではgenerator-critical-path 2.1.0／2.2.0の保存済みparameters.valuesのA〜Hを初期条件にする。問題文を解析したり最新の生成器で再生成したりせず、操作用状態だけを変更する。「初期値に戻す」はその保存済み条件と両ダミーを復元する。

参照追加に伴い原問題を改訂3、基準問題とテンプレートを改訂8へ更新する。生成器の計算と入力域は変更せず2.2.0を保持する。基準hash、セットの参照、カタログ、ブックマークの改訂対応を更新する。旧snapshotに詳細参照を補完せず、旧本文・通常解説・正答・結果を保持する。

## 検証方法と範囲

tests/arrow-simulator.test.tsでは原図から別に固定した接続表の全経路を列挙し、最早時刻、最遅時刻、余裕、完了日、全クリティカルパスを照合する。0・1・2日の全6,561入力×ダミー4状態=26,244ケース、原値、条件変更例、100個の再現可能な追加入力、60桁の整数、無効入力、計算順序、保存済み条件、旧版の再開・追加・復習、パッケージのhash・素材条件を検査する。小さい領域の全列挙と代表的な大きい値の確認であり、任意の全整数の網羅検証とはしない。同一AIによる査読であり、人の二重校正ではない。

ブラウザ用の確認スクリプトは `npx tsx scripts/verify-arrow-browser.ts <起動済みURL>` でoutput/playwright/arrowへ生成する。隔離したPlaywright CLIでverify.jsとgenerated.jsをrun-codeのfilename指定で実行する。指定された1362×1313と1280px、390／320px、両テーマ、表示領域の幅全体を使う配置、下部操作の位置保持、全作業の図からの直接編集、遷移ボタンの不在、予約領域の固定高さ、無効入力、結合式、ダミー、複数経路、再生、フォーカス、元画面への復帰、生成問題の保存済み値を確認する。generated.jsは専用ブラウザのIndexedDBへだけ検証用記録を保存する。

資源を変更したら `node scripts/update-arrow-manifest.mjs` で共通色・スクロール実装の複製とmanifestを更新する。完了時には `npm run check` を通す。ローカルでの成功を公開サイトへの配信完了とは扱わない。
