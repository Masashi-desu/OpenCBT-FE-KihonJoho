# ハフマン符号化とデータ圧縮

2018年度秋期 基本情報技術者試験 午前 問4の詳細解説。PCMの数値と図の対応、2進数変換の段階操作、D/A変換の図と式からの選択を参考にする。

## 学習の焦点と操作

主図の上に問いの要点と問題の符号表を置く。文字を横に並べ、出現頻度と符号を同じ列で読めるようにする。Dの欄は出題時の空欄 a を表示し、求めた符号は木の経路と式で示す。表の文字を選ぶと木の葉と説明が連動する。結合中は足し算の各項に含まれる文字の頻度を同じ色と下線で示し、途中で得た重みが元のどの頻度から来たかを追えるようにする。同じ重みがあるときは、表で既知の符号の先頭ビットから組を選ぶ理由を説明する。根の100%は全5文字を集めた重みとして、次にDの経路を読む起点になる。

- 出現頻度の小さい2節を一つにまとめるたびに、足し算の項と木の節を対応させる。併合した節と元の2節を強調し、まだ親を持たない節を太枠で示す。同じ重みの節が候補になるときは、問題で与えられた符号表に合う組を使う。枝は左を0、右を1とする。
- 木が完成したら、根からDへたどる枝のビットを順に読む。全4択を選んで、既知の符号と一致するか、どちらかがもう一方の接頭語になるか、Dの葉に到達するかを木上で確かめる。原問のDは110。類題では保存された表と選択肢順を使い、Dが2ビットの場合や枝の左右が変わる場合も同じ操作で確認できる。
- 例示の文字列 ABCDE を一文字ずつ置き換え、各文字の経路と対応するビット列を確認する。例示の5文字では固定長15ビット、ハフマン符号12ビット。出題の頻度どおりに100文字ある場合は各文字の出現回数×符号長を合計して225ビット。固定長は5種類を区別する3ビット×100文字で300ビット。棒の長さで75ビット（25%）の削減を比較する。符号表などの付加情報のビット数は比較に含めない。

頻度、4回の結合、Dの符号、文字列の符号化、全体のビット数を「戻る」「次へ」とスライダーで往復する。節、例示のビット列、合計式の項を選ぶと、同じ節や枝と式が強調される。選択肢を試す操作は符号を読む段階で表示する。同じ対象の再選択またはEscapeで解除し、操作元にフォーカスを戻す。ステップを移動すると選択を解除する。頻度は出題条件として固定し、入力欄や自動再生は設けない。

主図は作業領域の全幅を使う。結合前から最終配置に必要な4段と下端の葉の領域を確保する。幅900px以上の解説では、表・木・式を同じ画面で見比べやすいように図を標準の文字サイズで15remに収め、文字を拡大すると節と枝のビットの間隔を広げる。それより狭い幅では図を17remとし、問いの下に表を並べる。文字拡大時は必要な場合だけ表と図の内側を横スクロールする。ステップと選択によって表・木・主要操作の位置は変わらず、説明と比較は操作より後ろで自然に伸びる。埋め込みでは共通ホストの高さ追従と出典欄を使う。
