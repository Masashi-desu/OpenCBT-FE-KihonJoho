# 問題作成・可変問題の品質規約

## 適用範囲と正本

本規約は、既存問題の修正、新しい可変条件・生成器・選択肢・解説・図の作成、収録年度・公開問題の追加に適用する。現在の収録件数・生成器版・特定の年度を適用範囲の上限にしない。問題作成と品質判定の正本はこのページ、実行手順はリポジトリのfe-question-generationスキルとする。フィールド名・値域・登録形式はSchemaとコードに従い、本規約のために別のデータ形式を作らない。

[取り込み・権利](/ingestion)、[本文形式](/content-format)、[生成・描画の実装](/diagram-generation)、[必須テスト](/acceptance#生成内容と正答の必須テスト)、[保存・訂正](/maintenance)も適用する。以下の項目は作問ごとの査読・自動テストへ対応付ける。規約を追加しただけで既存全入力の品質を検証済みと記録しない。

## QA-01 — 原資料と出題意図を固定する

公式掲載元、問題冊子、解答例を特定し、年度・科目・問番号・ページ・確認日・原資料のhashを記録する。OCRや抽出文字だけで転記を確定せず、図、表、空欄、選択肢の対応を原資料の見た目と照合する。公式解答の記号と選択肢IDの対応も確認する。利用条件と第三者部分は[取り込み工程](/ingestion#ing-03-—-取り込み工程)に従って素材・用途別に判断する。

作成前に、学習対象、問いの方向、肯定・否定、求める対象、判定条件、選択肢の数と役割、文章・表・図・空欄・疑似言語の構成を記録する。この構成を保って対象・条件・値を対応する位置へバインドする。説明を選ぶ問いを名称の識別へ変更するなど、答えを変えるために別の問いへ置換しない。原問題に固定入力がない場合、動作確認用の引数を公式の固定値と記録しない。

原問の固定入力を使う基準問題では、計算結果と数値選択肢を原資料に照合する。知識・式・プログラムの選択肢では、全選択肢の意味・役割・正誤対応を照合する。言い換えや独自作図を行う場合は改変として追跡し、変えた内容と維持した意図を残す。

## QA-02 — 前提・文章・表記を一致させる

「ここで」「ただし」「なお」、図表の注記、疑似言語のコメントも本文と同じ確認対象とする。記号の定義、対象期間、単位、入力域、添字の開始位置、未定義要素、端数処理、繰返しを実行しない条件を、解答前の本文・参照本文・図表で読めるようにする。解説や読み上げ用のaltだけで補わない。

対象を変えたときは、元の対象に固有の前提・用語・目的・助詞・例も更新する。同じ言葉に異なる意味を与えず、条件によって解釈が分かれる問いには必要な条件を置く。「以上」「超える」「最少」「最大」「適切でない」など、正答条件を変える表現を省略・追加しない。生成した文章が自然な日本語になり、述語と解答対象が対応することを確認する。

数量は対象に応じて扱う。平均客数には端数を使えるが、配列の要素数など離散個数へ端数を使わない。百分率とパーセントポイント、時間と分、バイトとビット、十進接頭辞と二進の単位を混同しない。原資料の単位・記号の意味を維持し、変更が必要なら関連箇所も同じ入力から更新する。

## QA-03 — 計算精度と負担を原問題へ合わせる

数値をランダムに選ぶ前に、原問題の入力の桁数・刻み、途中計算の規模、必要な計算回数、答えの精度、丸めの位置・方向、選択肢の間隔を査読する。生成問題でも同じ概念・手順で解けることに加え、四則計算・状態追跡・概算で選択肢を区別する負担を原問題へ近づける。

原問題が正確に求まる答えを問う場合は、答えが適切な桁数で求まる入力を生成する。乱数の都合による長い割算を解かせたり、近接した誤答を作るために追加の切上げ・切捨て・四捨五入を要求したりしない。金額・時間などは意味と現実性を保つ扱いやすい刻みを選ぶ。単に整数に丸めて問題の条件や利益の等式を変えない。

原資料が指定する端数処理は、途中・最終結果のどちらへ適用するかも含めて維持する。入力の変更で表現精度の小さな拡張が必要になる場合は、同じ概念・計算負担を保てる理由、許す精度、表示条件、境界の検証を記録する。例えば1桁の16進小数を小数第3位までで正確に表す扱いを、他の計算問題で精度を増やす一般的な許可にしない。

系列ごとに、基準入力、入力の刻みと相関条件、許す表示桁数・計算精度・選択肢間隔の基準を、実装前に査読値として固定する。正答が0又は負数の場合や単位・規模が変わる場合は、正答で割る相対距離を機械的に使わず、絶対距離や入力規模に基づく比較を選ぶ。現在の「正答と誤答の相対距離を原問の半分以上にする」基準は適用可能な数値系列の手法であり、今後の全形式へ無条件に流用しない。

## QA-04 — 誤答を意味と区別のしやすさで設計する

誤答は、利益・変動費・制御情報の計上漏れ、単位の取り違え、依存関係の見落とし、添字・繰返し回数・条件式の誤り、似た概念の取り違えなど、その問題で起こり得る誤りから作る。原問題の誤答の構成と解答に必要な判断を基準にし、全系列を共通の「正答±1」「正答±最小表示単位」で作らない。

原選択肢の間隔を基にした比例調整等で候補を補う場合は、その根拠と適用範囲を記録する。補充を口実に正答の近傍へ密集させない。正答を求めた後、表示精度まで確定した全選択肢を評価し、重複、丸め後の一致、同義表現、偶然正答となる条件、率の範囲外など不要な除外だけで解ける候補を検出する。元の問いが範囲外・成立しないものを識別する形式なら、その判定を維持する。

正答だけが細かい小数、長い説明、違う単位・語調になるなど、新たな外見上の手掛かりを作らない。数値の大小・選択肢位置・特定語句の出現だけで正答を推測できる偏りを増やさない。ただし、その偏りを取り除くために原問題の問いの方向や選択肢の役割を変えない。並べ替え後の表示記号と正答IDの対応も検査する。

今回の損益計算では、原選択肢「3.75・4・4.2・5」に対し0.01人刻みの誤答を作る扱いが不適切だった。利益の計上忘れ・変動費の差引き忘れ等を使い、正確に求まる客数と原選択肢に見合う間隔を確保する。この事例を、全問題を易しくする指示や固定の0.25刻みを使う指示へ一般化しない。

## QA-05 — 入力域と生成の多様性を両立する

入力域は各フィールドの最小・最大だけでなく、刻み、列挙候補、値同士の相関、整数解・正の分母・一意な最大などの制約も含めて定義する。本文・表・図・選択肢・正答・解説を同じ入力から生成し、どれかを別抽選したり、生成後に正答へ合わせて条件を付け替えたりしない。

条件を変えた入力でも原問題と同じ解法・処理を使えることを確認する。知識問題は名称の置換と並べ替えだけでなく、問いを維持したまま対象・状況・誤答の意味を変える。列挙を問うなど正答が固定される形式では、正答を変えるために問いを変えず、変更可能な誤答や条件を定義する。

刻みを粗くして計算負担を下げる場合も、基準入力・直前入力・直前の正答・練習内の重複回避に使える候補が十分に残ることを検査する。同じ系列を複数回使うセット、ブックマークの個別／全件練習、無限周回を確認する。候補が枯渇したときに原問題や以前の問題を黙って再利用しない。抽選・再試行は有限の上限を持ち、成立しない条件・容量不足を明示的に扱う。

シード、テンプレート改訂、生成器版が同じなら内容を再現できるようにする。特定の答え・分岐・条件へ意図せず偏る抽選や、正答を隠すためだけの不適切な変形がないかを査読する。正答の全位置・全値が必ず同じ頻度になることを、形式上成立しない系列へ要求しない。

## QA-06 — 知識・アルゴリズム・図表の意味を検証する

| 対象 | 作問時に保持・検査するもの |
| --- | --- |
| 知識 | 適用条件、対象時点、肯定・否定、正しい対応、全候補の意味と根拠。査読して固定した資料を使い、生成器の対応表から期待値を自動更新しない。年度・制度・標準・用語の変更を別問題へ無断で混ぜない |
| プログラム・空欄 | 添字、型、初期状態、入力域、停止条件、例外・未定義・領域の重なり。正答は許された入力で要求する処理と等価、誤答には独立した反例があること。一つの実行例の一致だけで式や処理の等価性を判断しない |
| 表 | 行列と単位、見出し、非表示部分、集計条件と表示値。表と本文・計算で同じ対象を扱い、解法を教える新しい補助表に置き換えない |
| 図 | 向き、接続、依存、凡例、軸・目盛り、上下ラベル、ダミー、状態。パラメータの変化後も意味と読取り方を維持し、文字の重なり・欠け・接続誤りをレンダリングで確認する |

管理された描画器と生成器を使い、表示する疑似言語やデータ由来の任意コードを実行しない。図の通常表示と読み上げは同じ条件を伝えるが、解答に必要な条件を読み上げだけに置かない。

## QA-07 — 独立検算・境界・表示を必須にする

[生成内容と正答の必須テスト](/acceptance#生成内容と正答の必須テスト)を適用する。正答IDの存在、Schema適合、再現性、対応件数の成功だけでは、内容の正しさや難易度の適合を完了と扱わない。

- 基準入力、最小・最大、ゼロ、等値・大小の分岐、丸め境界、成立しない組合せ、異なるシードを、系列の性質に応じて検査する。
- 小さく全列挙できる候補・状態は全列挙する。大きい域は同値類・境界・不変条件と再現可能なシードを併用し、検査範囲と未検査範囲を残す。現在のシード数を将来の全系列に十分な定数としない。
- 独立解と、実際に表示する入力・全選択肢・正答ID・解説の結論を照合する。意味のテストには、生成器の正答を期待値へ流用しない。
- 数値系列では計算精度・選択肢間隔・丸め後の一意性も査読基準と比較する。解けることと、原問題に見合う計算負担で解けることを別に検査する。
- 表示では解答前の本文・図表を確認する。静的レンダリングで満たせる確認を先に行い、作図・長文・選択肢の配置等を変えた場合は必要な画面検証も行う。ブラウザ面の選定は既存の検証スキルとユーザーの指定に従う。
- 指摘された不具合の入力と検出条件を回帰テストに残す。未登録・skip・期待値の付替えで失敗を消さず、同じ方式を使う他系列にも影響範囲を広げて確認する。

## QA-08 — 解説・査読記録・限界を残す

解説は表示した条件だけから結論へ到達し、単位、端数処理、主要な計算・分岐を本文と一致させる。答えの記号だけを示す説明、結論を正しく見せるために解説へだけ前提を足す説明を作らない。独自解説を公式解説と表示しない。

各系列の記録に、次を既存のreview.notes、独立したテスト用資料、検証記録等で対応付ける。追加の前提がない、丸めがない、正答が固定されるなど、該当しない項目も理由を示す。新たなSchemaや専用管理システムを必須とするものではない。

| 記録項目 | 記録する内容 |
| --- | --- |
| 原資料 | source・locator・公式解答、確認日、素材ごとの利用条件 |
| 原形式 | 学習対象、問いの方向・判定、媒体構成、注記、全選択肢の役割 |
| 可変設計 | 固定する部分、変更する部分、入力の刻み・相関・禁止条件、候補数・重複回避 |
| 精度・難易度 | 原入力と原選択肢、表示・計算精度、計算負担、誤答モデル、比較基準と調整理由 |
| 検証 | 系列・生成器版、独立解又は固定資料、境界・全列挙・シード、表示確認、回帰ケース |
| 結果 | 実際の確認主体・方法、成功・未解決事項、未検査範囲、公開版・保存互換への影響 |

「試験に近い」は上記の作問基準に対する設計目標である。受験者の解答データによる難易度・識別力の実測がなければ、本試験との統計的等価性を確認済みと表示しない。有限のテスト、同じエージェントによる査読、Schema成功を、第三者査読や外部事実の証明と記録しない。

## QA-09 — 公開問題・年度の追加手順

追加を依頼された範囲の公式掲載・冊子・解答例・利用条件を再確認する。既存年度の問数・素材条件を新年度へ流用せず、追加範囲の用意可能な問題と除外理由を全件列挙する。この規約から、対象外年度の自動収集・将来の定期監視・外部公開の実行を推定しない。

| 段階 | 完了条件 |
| --- | --- |
| 範囲・出典 | scripts/source-inventory.ts、source・rightsの記録、収録範囲の説明が実際の公式公開と一致。第三者部分を個別確認し、除外には根拠・理由・確認日を残す |
| 原問題 | 年度別オリジナルの原文・画像・選択肢順・公式正答を照合し、既存IDの使い回しや既存公開版の上書きをしない |
| 生成一式 | 各用意可能な原問題に、完全な基準問題・登録生成器・必要な描画器・科目のミックス枠・独自解説・出典表示を一対一で揃える |
| 意味と品質 | 新系列を独立解／知識資料、原形式・前提・精度・選択肢・表示・容量の査読とテストへ登録する。年度の件数だけを更新して対応済みにしない |
| 設定・参照 | カタログ、年度別セット・試験設定、ミックス候補、ブックマーク等の参照を追加内容に合わせる。実際の候補数と1回の出題数を混同しない |
| 文書・検証 | READMEの範囲、生成対応一覧、必要な期待件数・公式解答キー・検証記録を更新。対応件数は原資料から求め、103等の現在の値を固定上限にしない |

`generationCoverage: "complete"` を維持し、用意可能な原問題と有効な生成一式の欠落・二重登録を拒否する。問題と生成器を両方削除して全件対応と扱わず、メニューの対応件数や未対応の告知で不足を代替しない。条件未確認の素材は用意可能とみなさず、根拠が得られるまで既存の除外も維持する。

## QA-10 — 版・保存互換・訂正を分ける

公開済みの本文・選択肢・入力域・計算・解説を変える場合は、影響する問題改訂・生成器版・テンプレート参照・内容hash・配布カタログを更新する。新規開始を新版へ切り替えても、既存の出題内容・選択肢順・正答・結果を黙って再生成・再採点しない。

保存済みの正常な記録は、当時の入力域・生成器・描画器の契約で再開・復習できるようにする。問題追加を認める旧練習でも、既存問題を維持し、新しく追加する問題の版と参照を整合させる。未公開で一度も配布していない版のためだけに後方互換を増やさない。公開済みかどうかは配信・改訂の記録から判断する。

正答誤り、複数正答、権利条件変更による停止は、正常な旧記録の互換とは区別し、[訂正・取り下げ方針](/maintenance)に従って通知と影響範囲を更新する。品質改善だけで正常な旧記録を削除しない。

## QA-11 — 完了時の確認

内容の確認と利用条件の確認を両方満たし、次を完了条件とする。規約・説明だけの変更では問題データを再生成せず、文言を写すだけのテストを追加しない。

- 対象内の用意可能な問題を全件揃え、QA-01〜QA-10の該当項目に査読・検証の記録がある。
- 意味・精度・選択肢・表示・保存互換の必要なテストが成功し、未解決の必須項目を残して配布を完了しない。
- `npm run data:validate` と `npm run test` が成功する。対応・登録契約を変更した場合は `npm run doc:generation`、Schemaを変更した場合は `npm run doc:reference` で正本由来の文書を更新する。
- 最後に `npm run check` で本体テスト・配布検証・型確認・本体ビルド・文書ビルドを通し、確認範囲と限界を記録する。
- 変更対象外の原問題・素材・保存内容を保持し、表示する出典・改変・素材条件へ到達できる。

これらは問題の作成・配布可能な成果物の確認である。ローカルの検証成功を公開サイトへの反映完了と記録しない。
