# 受入条件と検証規則

## 今回の文書・サンプルの受入条件

| 条件 | 確認方法 |
| --- | --- |
| 既存変更を守る | 作業前git status、既存構成・規約確認。今回の既存追跡ファイルは.gitattributesのみ |
| 文書だけを起動 | ルート `npm run doc` がdocs配下の文書サイトを起動する |
| ローカル閲覧 | 127.0.0.1で待受け、URLを表示、HTTP応答を確認 |
| 全仕様へ到達 | 全仕様ページをサイドバーへ列挙し、文書リンク・元JSON・Schemaを検査。ブラウザでナビゲーションと目次も確認 |
| 日本語・長い内容が読める | 独立した表・コードの横スクロール、狭い幅でページ全体の横はみ出しを確認 |
| 一次情報に追跡可能 | R01〜R25で対象・日付・箇所・事実・仕様対応・限界を記録 |
| 実行と記述が一致 | 元Schemaから全フィールド辞書を生成し、JSONの掲載はスニペット。名前・改訂・選択肢ID・出典表示を照合 |
| 有効サンプルが通る | 14Schema、35レコード、数式入力・画像・図・生成記録・出題経路と改変表示の保存・参照・モード・配布境界の検証 |
| 不正例が拒否される | 51例について期待するコードが実際に発生することを確認 |
| 文書のビルド | `npm run doc:build`。リンク・スニペットの失敗を無視しない |
| 文書と本体の分離 | 文書用サンプルが本体配布へ混入しない。文書への実行可能CBT埋め込みなし。公開・pushは行わない |

実行した結果と実行していない範囲は[検証記録](/verification)に示す。実行済みの本体試験と未検証項目を分けて記録する。

## 不正例と拒否する層

| 例 | 層・コード | 理由 |
| --- | --- | --- |
| 公式出典が空 | Schema `SCHEMA` | official_reprint／adaptationのsourceRefsは1件以上 |
| 正答が存在しない選択肢 | 整合性 `ANSWER_CHOICE` | IDの存在はSchemaだけでは確認できない |
| 存在しないsource ID | 整合性 `SOURCE_REF` | 出典への参照を解決できない |
| ID・改訂重複 | 整合性 `DUPLICATE_ID` | 同じ不変キーが2件ある |
| 画像参照切れ | 整合性 `ASSET_REF` | 本文からassetへ解決できない |
| 同梱条件未確認 | 配布条件 `RIGHTS_USE` | sourceの存在で利用条件を代用できない |
| 第三者条件未確認 | 配布条件 `THIRD_PARTY` | unresolvedは拒否 |
| 自己派生・循環 | 整合性 `DERIVATION_CYCLE` | 派生の祖先を特定できない |
| 表の列数不一致 | 本文整合性 `TABLE_SHAPE` | 行列の関係は別検証 |
| 危険なパス・SVG | Schema `SCHEMA` | 安全な静止画像の相対パス以外を拒否 |
| javascript等のURL | Schema `SCHEMA` | HTTPS以外を拒否。認証情報付きURLは `UNSAFE_URL` |
| 保存した選択肢順が欠落 | セッション `SESSION_CHOICE_ORDER` | 定義の全選択肢と過不足なく一致させる |
| studyで時間切れ | セッション `SESSION_TIMING` | studyに期限はない |
| docs_onlyが本体配布へ混入 | 配布条件 `RELEASE_GATE` | distributionカタログはincludedのみ |
| 文書用カタログで問題を配布対象に変更 | 配布条件 `RELEASE_GATE` | docs_fixtureとincludedを混在させない |
| snapshotの版・hash違い | 整合性 `CATALOG_HASH` | 当時の内容を特定できない |
| ファイルhash違い | 整合性 `FILE_HASH` | 配布許可リストとバイト列が一致しない |
| HTMLブロック | Schema `SCHEMA` | 未知typeを実行しない |
| 2問セットへ60問設定を関連付け | セット `SET_CAPACITY` | 開始可能な設定の条件を満たさない |
| 改変フラグ欠落 | Schema `SCHEMA` | 全問題でisModifiedを必須とする |
| 改変有無へ文字列を使用 | Schema `SCHEMA` | 作成時にbooleanとして明示し、推定変換しない |
| 元データ固定hashの欠落・不一致 | Schema `SCHEMA`／照合 `TEMPLATE_ORIGINAL_HASH` | バインド前のquestionが不変参照・内容hashに一致しない |
| バインド済み内容を改変なしとして保存 | 経路整合 `BINDING_MODIFICATION` | 値を生成・バインドした出題ではtrueを保存する |
| 出題方式と実施記録の不一致 | 経路整合 `BINDING_RECORD` | 元データ使用をバインド済みとする記録等を拒否 |
| 比較対象の参照欠落 | 参照 `MODIFICATION_REF` | 原資料又は基準問題へ到達できない |
| 出題時の改変情報の不一致 | 保存整合 `ISSUED_CONTENT` | 改変・出自・内容hashが実際のquestionと一致しない |
| 生成済み内容hashの不一致 | 保存整合 `INSTANCE_HASH` | 保存した出題内容が特定できない |
| 未登録描画器 | モジュール `RENDERER_REF` | ID・版が登録済み契約にない |
| 図の端点切れ／ID重複／添字不一致 | 図 `GRAPH_REF`／`DIAGRAM_ID`／`DIAGRAM_INDEX` | 同じ図内の参照と表示順が一致しない |
| 図へのCSS・実行コード混入 | Schema `SCHEMA` | 許可した宣言的構造以外を持ち込めない |
| 生成パラメータ域逸脱 | 入力 `PARAMETER_DOMAIN` | Schemaの型を満たしてもテンプレートの域を外れる |
| テンプレート参照切れ／未登録生成器 | 参照 `TEMPLATE_REF`／`GENERATOR_REF` | 固定契約を解決できない |
| 派生元・出典・条件の除去 | 生成整合 `GENERATION_LINEAGE` | 原問題との対応を失っている |
| instanceの所有者・位置の不一致 | 保存整合 `INSTANCE_BINDING` | 一つのセッションの出題枠へ一致しない |
| 結果のinstance参照の不一致 | 保存整合 `RESULT_REF` | 当時の出題内容を説明できない |
| 生成結果の正答が未知の選択肢 | 整合性 `ANSWER_CHOICE` | 通常問題と同じ存在検証を生成済みquestionにも適用 |
| 数式format不明／alt欠落 | Schema `SCHEMA` | 許可する形式と説明文を必須条件にする |
| 数式のリンク・マクロ命令 | 入力 `MATH_COMMAND` | 公式KaTeXの全機能を問題データへ開放しない |
| 数式の区切り・コメント | 入力 `MATH_SYNTAX` | ブロックのtextに数式本体だけを持つ |
| 数式の括弧・環境・行列上限 | 入力 `MATH_STRUCTURE` | 深さ16、環境の対応と非入れ子、8行・8セル以下 |

固定問題の改変の有無は作成時に原本へのリンクから照合する。出題時はbindingMode、バインド実施記録、instanceの有無を照合し、バインドした枠を改変あり、元データ使用の枠を元questionの表示維持として検証する。内容のテキスト・図・パラメータ差から判定しない。元データの作成時の宣言が正しいことを構造検証で保証しない。

メモリ内の候補で、履歴種別から改変有無を逆算しないことと、基準値をそのままバインドしても出題経路からtrueを保持することを確認する。元データ使用と生成値使用の二つの固定サンプルも検証する。記録・表示仕様の検査であり、生成器やユーザー保存機能を実行した結果ではない。

上記以外もsource／rights／actor／context／set／exam／session／resultの参照、MIME署名・サイズ・PNG寸法、科目、重複系列、時刻の逆転、保存期限、結果の件数整合を検証する。誤ったJSON自体を解析できない場合は読込み時に即失敗する。

文書用の数式検証は許可命令・禁止文字・括弧・環境上限の静的検査であり、KaTeXの完全な構文解析、実組版、MathMLやフォントのアクセシビリティ検証ではない。これらを通過したことだけで本体の数式表示準備を省略しない。

## 資料・内容・権利の受入条件

新規ミックスの生成器2.1.0／3.2.0では、原問題の問いの方向・正誤条件・解答対象・選択肢の役割と数、文章・箇条書き・表・図・空欄を照合し、出力形式を崩さずに抽象化する。説明を選ぶ問いを名称や誤対応を選ぶ問いへ変えた場合、同じparagraphの構成でも拒否する。文章問題へ条件表を追加しないこと、表形式の選択肢、空欄付き疑似言語と文章図の保持を確認する。登録契約にないブロック・選択肢形式はSOURCE_FORMATで拒否する。正答を選ぶ各空欄は複数の入力で元のアルゴリズムと等価であり、誤答は等価でないことを検査する。保存した問題を現行の生成器で作り直して訂正済みと扱わず、旧記録は当時の内容で説明する。

収録前の資料・内容の確認では、公式公開箇所、利用条件の対象、第三者の部品、媒体別の用途、必要な出典・改変表示、原文との一致、正答の根拠、独自解説の論理、図表・代替文を確認する。公開用includedへ組み入れる場合はこれらの確認結果と証跡を保持し、問題の有効性と全条件を確認する。確認主体が人かAIかを正しく記録し、担当分離や人による二重照合を実施していなければ実施済みと表現しない。

Schema成功は適法性、著作物性、特許不存在、公開資料の適法な由来、正答・解説内容の真実性を保証しない。機械フラグのpassも記録した工程結果であり、根拠資料を確認せずに値だけを設定してはならない。

## 本体の受入条件

以下を本体の受入条件とする。実行結果は[実装検証](/implementation#検証)へ記録し、全項目を一括して確認済みとは扱わない。

- S01〜S11の全遷移、未解答と見直しの両立、選択・変更・解除と保存の対応。
- 解答・復習のヘッダーは上段に本アプリ固有の情報・補助操作、下段の左に資料一覧・手・＋／−・ズーム選択、右に時計・終了操作を置く。問題資料・解答領域と同じ列幅で分割し、左右の高さと境界位置を揃える。指示された操作だけを追加・置換し、補足ラベルを設けない。狭い画面で折り返しても両段の項目を混在させない。
- 選択肢の行から解答でき、丸いラジオボタンや右端の選択・正答チェックに表示幅を使わない。選択は枠・背景と読み上げの状態で分かり、クリック・矢印キー・Spaceでの選択／解除を維持する。選択・解除・正答表示でも本文・図表の幅を変えない。
- practiceの期限到達、バックグラウンド、再読込み、確認ダイアログ中の時間切れで期限が延長されない。
- studyの明示停止と予期しない終了からの復帰、revealed履歴の保持。
- 問題資料に表示した本文・図表を解答領域へ重複表示しない。年度別・生成練習・ブックマーク・復習に共通で適用し、狭い画面の縦並びでも必要な本文・条件・図表を維持する。
- 問題不足、年度別の同一系列又はミックスの同一入力重複、参照切れ、保存失敗、競合タブ、hash不一致、clock_changeで続行を止める。
- question訂正・withdrawalsで過去結果の表示が説明され、撤回された素材を再表示しない。
- 公開停止した資源が管理下の公開旧版・Git履歴・配布物・文書からも除去対象として確認され、通知に本文・素材・非公開情報を再録しない。Schema検証だけでこの工程の完了を保証しない。
- 正答データのクライアント配布の限界と公式成績との差がS02・S06に表示される。
- 問題ごと・画像ごとに出典、改変、独自解説、第三者条件がS03・S06・S07・S09へ維持される。
- 資料一覧からページを開け、手ボタンは選択中の背景・アイコンを反転表示し、ドラッグで本文と図表の縦横スクロールが動く。ズームの各モードと50〜400％、＋／−の境界が機能し、右の解答欄や保存済みの問題・選択肢・正答を変えない。
- キーボードだけで完遂でき、ダイアログのフォーカスが戻り、200%文字拡大・320px幅・非色依存・読み上げで操作できる。
- IndexedDBの180日削除、1件／全件削除、未参照snapshotとassetの整理が成立する。
- 任意HTML・未知ブロック・外部画像・危険URL・過剰サイズを拒否し、疑似言語が実行されない。
- 配列・フローチャート・グラフの登録済み描画がsceneと一致し、読み上げ用代替説明・素材条件を維持する。原図にない説明・接続表・内部IDを出題画面へ追加しない。アローダイアグラムの円形節点、上下の作業名／日数、破線、凡例を維持し、狭い幅と文字拡大は図の領域内スクロールで扱う。
- 原画像・記述から定義した103生成器を基準値と64シードずつで検査し、図・表・本文・誤答・解説の整合性を確認する。数値・アルゴリズムは別方式でも検算し、知識の定義と構造の一致を真実性の自動証明と混同しない。アローダイアグラムはダミー作業を含む全経路の探索でも照合する。既存array-sumの729通りは説明用・旧保存契約の互換検査とする。
- ランダムミックスに固定問題・未生成枠を含めず、全枠のinstanceと改変ありを保存する。同系列の別入力は許可し、同じ入力の重複、直前セッションの入力、正答を変えられる問いの直前の正答値を避ける。正しい列挙が固定された知識は、原形式を優先し、誤答の意味・条件を変える。生成できない場合は開始しない。
- 同じtemplate・generatorの版とシードから同じ出題内容を作り、移動・再開・復習では生成を再実行しない。準備失敗時はタイマーを開始しない。
- 元question・template・依存素材をバインド前にsnapshotへ固定し、生成後も元内容を上書きしない。元データ使用では入力抽選・生成器を呼ばず、基準の本文・図・正答・解説を使う。
- bindingModeとbindingPerformedを保存し、バインドした枠は基準値と同じでも改変あり、元データ使用では既存の改変表示を維持する。無断の経路切替や再開時の再判定を行わない。
- isModifiedと改変履歴を全画面で保ち、正答を含むanswerDetailsをpractice終了前に表示しない。内容hash・所有者の不一致を再生成で隠さない。
- テンプレート・生成器・基準問題の撤回が保存instanceへ伝わり、削除・180日保持・権利理由の本文削除が全体で成立する。
- S01の「ライセンス」からS11へ移動し、原著作権表示・原文全文・採用版・適用範囲を確認して、選択内容を保ったS01へ戻れる。キーボード操作とフォーカス復帰が成立する。
- CDN・カタログ障害時にもメニューとS11が閲覧でき、通知ファイルの欠落・採用版の不一致をリリース検証で拒否する。出題・復習の個別出典表示も維持する。
- 代表的な分数・指数・対数・総和・床天井・行列・場合分けの実組版、許可外命令・不正構文の拒否、MathML・alt・文字拡大を確認する。
- 固定CDN URLとSRI、CSP、必要フォント、10秒の準備タイムアウト・明示再試行を検証する。準備失敗時は開始せず、復習時の一時障害で結果を無効にしない。
- 実ネットワークでKaTeX資産以外のCDN取得、問題・パラメータ・解答の送信がないことを確認する。専用オフライン機能を実装しない。

## ブックマークの受入条件

- 解答・復習画面のヘッダー補助操作で問題を追加・削除でき、時間付き練習でも正答を開示せず保存できる。原問題とその生成問題を同じ一件として扱う。
- メニュー左列から一覧を開ける。再読み込みで保存を保持し、履歴の個別・全件削除や180日保持によってブックマークを消さない。空一覧と個別削除を扱う。
- 一覧に元問題の文頭と分野名を表示し、以前に保存したブックマークでも内容を見分けられる。本文を保存データへ複製せず、原資料の出典・権利表記を確認できる。ライト・ダークと狭い画面でも文頭を読める。
- 収録済みの全原問題について、ブックマークから対応する系列の類題を開始できる。「次の類題」で直前と異なる入力を生成し、正答を変えられる問いでは直前の正答値も避ける。解答・結果・出典・改変表示を保存する。
- 再開・復習では本文・図表・正答・解説・選択肢順を再生成しない。生成又は保存に失敗した次問を開始しない。ブックマークの保存失敗だけでは現在の解答を停止せず、失敗した追加を保存済みと表示しない。
- 保存領域の版更新で従来の履歴を維持する。利用できなくなった原問題の参照を更新確認時に削除し、別問題へ自動置換しない。

## 全問生成対応の受入条件

- generationCoverage=completeの配布カタログでは、含まれる公式原問題すべてから有効な基準問題・テンプレート・科目別ミックス枠へ一対一でたどれる。未対応又は二重登録はGENERATION_COVERAGEで拒否する。
- ミックス候補はA80問・B23問であり、候補群の大きさと1回の出題数60／20を分ける。set.generationBindingsは最大500候補とする。
- 生成問題に固定画像を使わず、文章・表・図・空欄・元の選択肢数を保つ。未登録の図、値域違反、凡例不足を検査する。原文そのものの再録と改変基準問題の形式契約は別に扱う。
- 基準・直前の正答内容を避けて新しい条件を選び、移動・再読込み・結果・復習で生成済み内容を保持する。すべての開始で全103問が必ず選ばれると保証しない。
- 出典・改変の概要・素材条件は常時維持し、生成パラメータ・シード・基準問題・changes.details／answerDetailsは正答確認後又は終了後に表示する。生成入力が正答の手掛かりになるケースを出題中に露出させない。

## 公開前の追加検証

公式公開範囲をscripts/source-inventory.tsと照合し、原問題と生成器を両方削除して全件対応と称するデータをSOURCE_INVENTORYで拒否する。公式の正答表は別の確認用記録と照合する。改変問題の原出典と原部分の条件を削除した場合はSOURCE_INHERITANCE／RIGHTS_INHERITANCE、公式依存本文を独立作成と記録した場合はRIGHTS_PROVENANCEで拒否する。

各生成器の内容の正しさは、下記の必須テストで検証する。実際の確認範囲と限界は[公開前査読](/review)及び[検証記録](/verification)に記録する。

通知の範囲・版・原資料・原文hash、採用パッケージの通知全文との一致、実バンドルに含まれる依存の通知を検査する。不足はLICENSE_COVERAGE、版の不一致はLICENSE_VERSION、原文の不一致はLICENSE_TEXT、破損はLICENSE_HASHでビルドを拒否する。public/dataの配布許可リスト外のファイルは階層を問わずUNLISTED_FILEで拒否する。機械検査はライセンスの法的評価を代替しない。

## 生成内容と正答の必須テスト

本システムでは、問題・生成器・入力域・選択肢・正答・解説の追加又は変更に、内容の正しさを検証する自動テストを必須とする。構造検証と内容検証を分け、正答IDが存在することや、生成器が毎回同じ出力を返すことだけで内容検証を代替しない。以下を開発・配布の完了条件とする。

| 対象 | 必須の検証 |
| --- | --- |
| 計算・アルゴリズム・論理等の構造から解ける問題 | 生成器から独立した参照解法をテスト側に用意する。別の計算、全経路探索、状態追跡、真理値評価等で結果を求め、生成された本文・図表の条件、全選択肢、正答ID、解説の結論と一致することを検査する |
| 知識選択 | 問われる概念・説明・適用条件・正しい対応を、意味と出典を査読して固定したテスト用資料に保持する。用意された全対象・全選択肢・全出題方向の組合せを検査し、本文の問いを満たす選択肢と正答IDが一致することを確認する |
| 単一選択の全問題 | 本文の条件で全選択肢を評価し、正答条件を満たすものが一つだけで、そのIDがcorrectAnswer.choiceIdと一致することを検査する。複数正答、正答なし、同義の誤答、条件によって偶然正答と一致する誤答を拒否する |
| バインド・表示・記録 | 本文・表・図・疑似言語に表示する入力とバインド値の一致、入力から求めた解と独自解説の結論の一致、選択肢順の変更後も正答IDとの対応を維持すること、再開・復習で内容と正答を再生成しないことを検査する |

### 期待値の独立性

計算等の期待値を求める際に、生成器の正答計算関数、correctIndex、correctAnswer.choiceId、解説の結論を参照解法の入力や結果として使わない。生成器は検証対象の問題を作るために呼び出し、参照解法は問題に表示された入力又は表示との一致を検査したバインド値から解く。誤答も、その選択肢が表す計算・処理・条件を評価する。一つの説明例で結果が一致することだけで、アルゴリズムの等価性を判断しない。

知識の期待値は生成器の対応表からテスト実行時に再作成しない。根拠となる資料・確認箇所・適用範囲を追跡できる状態で査読し、テスト側へ固定する。原問題の問いの方向、肯定・否定及び正誤条件を固定し、用意された候補の意味をすべて評価する。対応資料の追加・更新は根拠の再確認を伴い、テスト失敗を消すために生成器の出力へ期待値を付け替えない。

### 入力範囲と検出能力

基準値だけでなく、境界、条件分岐、成立・不成立の組合せ、丸め、ゼロ、添字、移動領域の重なり等、その問題で起こり得る条件を検査する。小さく全列挙可能な入力・状態は全列挙する。大きい入力域では、同値類・境界・不変条件と再現可能な複数シードを組み合わせ、検査した範囲と未検証の範囲を記録する。禁止する組合せは、その入力が拒否されることも検査する。

テスト対象には系列・生成器版・入力範囲・期待値の根拠を対応付ける。正答参照の取り違え、別の選択肢も正答になる条件、表示値・解説の不一致を検出できる検証にする。過去の不具合を再現する入力は固定の回帰テストとして残す。新規系列を意味の検証対象へ追加し、未登録・skip・検証ケースの削除で成功させない。

現行の参照先はtests/generation.test.tsの既存系列の独立検算、tests/answer-semantics.test.tsの知識対応・追加系列の意味検証、tests/fixtures/knowledge-pairs.jsonの固定した知識対応、tests/full-coverage.test.tsの全系列・表示構造の検証、tests/source-question-form.test.tsの全103系列の問い方と方向変更の拒否検証である。tests/fixtures/source-prerequisites.tsは原資料から査読した全対象の前提・注記を保持し、tests/source-prerequisites.test.tsで基準値・異なる入力・境界の表示を検査する。追加の注意書きがない問題も記録し、対象を未登録にして検査を通さない。解説・選択肢・出典・SVGのtitle/descを除いた解答前の表示を検査し、解説や図の代替説明だけで条件を補うケースも失敗させる。将来の系列にも同じ条件を適用し、現在の件数や64シードだけを十分性の根拠にしない。

### 完了と保証範囲

対応する必須テストの不足又は失敗は作業未完了とし、配布を止める。用意可能な問題を削除して全件対応と扱わない。npm run test及びnpm run checkを成功させ、対象・入力範囲・根拠・結果を検証記録へ残す。内容の修正時は生成器版・問題改訂を更新し、既存記録と取り下げを[保守方針](/maintenance)に従って扱う。

テストが保証する範囲は、独立した参照解法又は査読済み対応資料に対して検証した入力・状態・選択肢の組合せである。有限の検査や知識の固定資料との一致を、全入力の検証又は外部の事実そのものの証明と表現しない。全入力域を検査した場合に限り、その範囲を全入力検証済みと記録する。
