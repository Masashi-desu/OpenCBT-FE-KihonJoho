# 更新・訂正・取り下げ

## MAINT-01 — 定期的な確認の範囲

本システムでは、問題を新規収録するたびと配布リリース前に、参照URL、公式公開、利用条件、第三者素材、正答訂正、FE制度・運営案内を再確認する。rights.checkedOnがリリース日から90日を超えて古い場合は再確認してからリリースする。自動監視・定期収集は初期版に追加しない。

sourceのURLが到達不能な場合、以前のhashと確認記録は残すが、最新条件が確認できたと記録しない。条件又は公式公開の確認を更新できない対象は新規配布から外す。確認できない理由を記録してsourceを推測で差し替えない。

## 訂正と改訂

| 変更 | 更新するもの | 既存セッション・結果 |
| --- | --- | --- |
| 組版・誤転記 | questionの新revision、changesとreview、catalogの新revision | 原snapshotを残し当時の版を示す。意味や正答が変わらなければ結果を保持 |
| 正答・意味 | 新question revision、必要な出自変更、検証、catalogのwithdrawalsにanswer_correction | 初期版は対象を含むセッションとsnapshotを全体削除する。黙って再採点・差替えしない |
| 出典情報 | 新source ID又は新question revision。原資料の情報を修復 | 当時の記録を保持し訂正内容を示す。根拠が成立しない場合は新規出題停止 |
| 権利条件 | 新rights ID、影響する全部品・派生問・assetを追跡 | 条件が不明・許可を失う対象は新規出題停止。表示・保存の許否も個別に確認 |
| 取り下げ | catalog.withdrawalsへ理由、対象ID・revision、日付、必要ならreplacement | 初期版は理由を問わず、対象を含むセッション、結果、元データ、instance、画像を全体削除し、復習でも表示しない |

公開済みの同じ問題ID・revisionを上書きしない。意味・正答・本文・出典・rightsの変更では新revisionを作る。独立した別の問いを作るときは新IDを発行し、依存するならderivedFromを残す。廃止IDを別問へ使い回さない。

## 取り下げ通知のデータ

`catalog.withdrawals[]` は `questionRef`、`category`、`reason`、`recordedOn`、任意の `replacement` を持つ。categoryは `answer_correction`／`rights_request`／`conditions_changed`／`source_unavailable`。撤回通知には問題本文・取り下げた図を複製しない。

これは問題等の資源を対象にした停止通知であり、利用者が画面で行った取消・終了・削除の履歴ではない。公開停止の判断は編集・保守工程で利用条件と対象範囲を確認して行い、Schemaはその判断内容の構造を検証する。reasonは利用者へ配布する説明文であって、資源を公開してよいかを機械判定する値ではない。通知に本文、選択肢、撤回画像、申立書、非公開の交渉内容を転載しない。詳細を配布できない場合は「利用条件の確認により、この問題の表示を停止しました」等の一般的な説明にする。

対象旧revisionが新カタログのquestion一覧から外れていても、通知は保持する。replacementは新カタログ内で解決できる別の不変参照とし、進行中へ自動差替えしない。派生元が撤回された場合、全子孫と共有asset・rightsへの影響を確認し、影響がない根拠を記録できるまで該当派生問を外す。

通知を残す目的は、過去の撤回を閲覧する履歴機能ではなく、端末に保存済みの旧snapshot・生成済み問題を特定して停止・削除することである。現行カタログに旧改訂がないだけでは、通常の新版への切替と、旧本文の削除が必要な撤回を区別できない。記録が法律上必須だとする趣旨ではなく、保存済み問題を扱う本システムの同期仕様である。既存questionRefを通知するだけで、撤回した資源を表示・再取得できる構成にしない。

## 撤回した資源と公開履歴の削除

権利・利用条件の確認により公開停止とした本文・選択肢・正答情報・図・画像は、最新版だけでなく、本プロジェクトが管理して公開する旧版、Gitの公開履歴・ブランチ・タグ、配布アーカイブ、生成済みサイト、公開した文書・サンプル・掲載画像からも削除対象を確認し、除去する。削除を示す通知へ対象本文を再録しない。「履歴の説明を保つ」「改訂は不変」という通常の訂正方針を、公開停止した表現の保存理由にしない。

端末側では対象snapshot・asset・instanceの本文を削除し、復習からも表示しない。通知には対象の識別と表示停止の説明に必要な情報だけを残す。初期実装は本文の残存を避けるため対象を含む結果も削除し、履歴の残骸を保持しない。問題を復元できる表現が通知・結果・出典記述に含まれている場合は、その部分も除去する。正答の誤りを訂正するだけで旧版の利用条件が維持される場合とは扱いを分ける。

公開元からの削除と通知配布は別の対応であり、通知を配れば公開Git履歴等の削除を省略できるとはしない。第三者のclone・fork等を本プロジェクトが遠隔削除できるとは保証しない。履歴を書き換えても他の参照やコピーに残り得る技術的な限界は[R19](/references#public-history-removal)に記録する。実際の削除範囲は対象資源と条件に応じて確認し、今回の作業では履歴書換えや外部削除を実行しない。

生成テンプレート・生成器・描画器の変更はIDと版を増やし、既存instanceを再生成しない。生成器の正答不具合は影響するtemplate.baseQuestionRefをanswer_correctionで通知し、そのテンプレート・生成器の版を持つ保存instanceへも適用する。初期版では同じ基準問題に関連する生成枠全体を止め、影響範囲を狭く推測しない。権利又は素材の撤回は基準問題、テンプレート、全生成結果、保存図を対象とし、本文・図を削除する。旧描画器の登録済み互換表示を使う場合も、元scene・入力・正答を再生成しない。未登録の描画器は復習を止めて更新が必要と表示し、接続表で出題形式を変えない。撤回・不正データを代替表示で再公開しない。

## 端末内保存と通信できない場合

アプリは起動時及び履歴の表示時に同一originのカタログを確認し、新しい撤回通知を取得できたとき対象snapshotを停止・削除する。通信できない場合、保存済みのセットを新規開始させず「更新確認が必要」と示す。既存の学習記録閲覧は、既に把握している撤回制限へ従う。

新通知を一度も取得していない端末、既に利用者がコピーしたファイル、Git履歴、外部fork、バックアップを遠隔で消去できるとは保証しない。権利者からの連絡に対応する場合は、今後の配布停止、公開先の削除、必要な履歴整理を別作業として扱う。公開リポジトリへのpushと、権利対応のGit履歴書換え・外部削除は別の操作として扱う。

本システムはオンライン利用を基本とし、専用のオフライン動作を保証しない。KaTeXの版変更では固定CDN URL・JavaScript/CSSのSRI・対応する原文通知・S11の採用版を同じリリースで更新する。旧questionの式を再計算せず、保存したtext・altを維持する。CDN停止は正答訂正や権利撤回と混同せず、準備失敗・復習時の説明表示として扱う。配布リリース前にKaTeX配布物の通知とjsDelivrの規約・プライバシーポリシーを再確認する。

## 結果の説明を保つ

結果は `sessionId` と `sessionRevision`、セッションのsnapshotと当時のquestionRef、生成枠ではgeneratedInstanceIdとissuedContentから説明する。結果のcalculationVersionを残し、現行版の正答で当時の値を静かに変更しない。表示を取り下げる必要があるときは、初期版では対象を含むセッション全体を削除する。元snapshotが全カタログを保持するため、当該問題を出題していないセッションも削除対象になり得る。

schemaVersion未対応、snapshot欠落、hash不一致では復習を拒否する。過去問題の識別に必要な出典の保存と、撤回された本文の再表示を分ける。

## 生成対応範囲の保守

原問題を追加・除外・取り下げる際は、直接派生する基準問題・登録テンプレート・ミックス候補を一緒に更新し、generationCoverage=completeの検査を通す。対象を除外した後の残る配布原問題について全対応を維持する。原問題の利用条件変更を独自図や生成正答の存在で無効化しない。

生成器2.0.0の既存13系列、3.0.0の追加86系列、査読で修正した3.0.1の4系列は別契約として登録する。未公開の初期配布データを構築するprepare-generation-data.tsの--refresh-additionalは追加系列の再構築用である。配布後に同じgenerator versionやquestion revisionを内容変更に使わず、新版を発行して保存済みsnapshotは旧内容で扱う。

2026-10-07の査読では2023A問10、2024B問2、2023B問6、2026B問1の生成用基準問題改訂2をanswer_correctionで通知し、差替え先を改訂3とした。対象を含む旧snapshotの削除は既存の端末内保守処理で行い、利用者の結果を再計算しない。旧3.0.0の登録コードは旧保存内容の検証・識別のため保持するが、現行カタログから新規出題しない。
