# アーキテクチャと安全性

## 選ぶ基本構成

本システムでは、React・TypeScript・Viteによる静的なクライアントアプリ、JSON Schema／Ajvによるデータ検証、IndexedDBによる端末内保存を採用する。初期規模ではサーバ、認証、API、DBサービス、課金基盤を必要とせず、問題と解答状態を分離した単一端末の学習を実現できるためである。

React・TypeScript・Lucideを採用する。JSON SchemaはAjvのstandalone生成でビルド前に検証関数へ変換し、ブラウザでevalやnew Functionを使わない。文書サイトとは起動・責務・配布データを分ける。バージョンはpackage-lock.jsonで固定する。

## 責務と処理の流れ

| 責務 | 保持する内容 | 保持しない内容 |
| --- | --- | --- |
| CBTエンジン | セッション状態、順序、期限、解答操作、終了、学習指標 | 元資料の年度表記や個別の権利判断 |
| FE設定 | 科目、問数、時間、B内訳、mode、採用機能 | 画面の公式コピー、非公開問題、IRT計算 |
| 問題データ | 共通本文、設問、選択肢ID、正答、解説、派生 | 利用者の解答・保存状態 |
| 出典・権利 | source、rights、asset、表示条件・確認範囲 | 出典ありを自動許可へ変換する処理 |
| 表示層 | 許可ブロック、独自UI、状態表示、出典帯 | 任意HTMLの実行、疑似言語の評価 |
| 図描画層 | 登録済みHTML/CSS/JS描画器、宣言的scene、原図の凡例、読み上げ用代替説明 | 問題データのコード実行、正答や利用者解答の取得 |
| 数式描画層 | 制限付きLaTeX、固定版KaTeXのCDN取得、組版・MathML・説明文 | 正答計算、任意HTML・URL・マクロ、解答データの外部送信 |
| ライセンス案内 | 本体・依存資産の版、原文通知、S01からS11への遷移 | 問題単位の出典・改変表示の代替、CDN依存の全文取得 |
| 生成層 | 不変の元データ、出題経路、版付きテンプレート、入力域、シード、全出題内容の確定 | 未登録コード、外部AI、表示用疑似言語の評価 |
| 保存層 | 不変snapshot、session、result、保存版・期限 | クラウド同期、個人認証、受験者の本人情報 |

本体は次の順で処理する。準備・検証の失敗ではタイマーを始めない。

```text
カタログ取得
→ バイト数・Schema・許可リスト・hash検証
→ source／rights／asset／question／set／examの参照検証
→ 条件を満たすセット・modeを表示
→ 開始時に順序とバインド前の元データsnapshotを保存し、選択した出題経路で内容・実施記録・改変表示を確定。バインドした枠だけinstanceを保存
→ latexを含むセットではCDN依存資産・全数式の組版を準備してからrunningへ移行
→ 許可ブロックと出典・権利を表示
→ 期限評価後に解答操作を保存
→ 終了状態を確定
→ 当時の改訂から学習結果を生成・保存
→ 復習・削除・訂正通知を扱う
```

## 安全性と外部通信

読み込む問題は未信頼データとして扱い、ローカルの固定Schemaに登録した型だけを受理する。外部からSchemaを取得しない。JSONとアセットにサイズ上限を適用し、パスをカタログ内の配布先へ制限する。SVGファイル、外部画像URL、任意HTML、スクリプト、埋め込みURLは受け付けない。[本文規則](/content-format)に従う。管理された描画・生成コードは本体へ組み込み、問題JSONにはID・版と宣言的データだけを持たせる。[管理モジュールの契約](/diagram-generation)を守る。

初期版では利用者が任意の問題URL・ファイルを取り込むUIを提供せず、編集工程を経た同梱カタログだけを読み込む。それでも不正データを検証せずDOMへ渡さない。画像は編集時の再エンコード・完全デコード後に固定し、ブラウザではimgとしてだけ表示する。

本体・カタログ・問題用アセット・ライセンス通知は同一originから取得する。外部通信の例外は[固定版KaTeXのJavaScript・CSS・付属フォント](/content-format)のjsDelivr取得と、利用者が出典・ライセンスの外部リンクを開いたときに限る。問題データでCDN URLを指定させない。広告、アクセス解析、クラッシュ送信、学習記録送信、外部画像、CDNでの問題取得は初期版に含めない。

CDNへ取得するのはライブラリ資産だけで、問題文・パラメータ・正答・利用者の解答をリクエストへ含めない。ただし、ブラウザの資産取得でIPアドレス等がCDNへ届く。Referrer-Policyをno-referrerとし、この通信をS01・S02とS11の案内に記載する。CDN事業者の保持・処理は[R18](/references#数式ライブラリとcdn)の確認範囲に従い、本アプリが外部通信を一切行わないとは表示しない。出典リンク先の通信は本アプリの管理範囲外である。

オンライン利用を基本とし、オフライン専用機能は初期版へ含めない。CDNの読込み失敗時は[数式の準備・復習の規則](/content-format)に従う。メニューとライセンス一覧はKaTeXに依存させない。

本体配信ではCSPを`default-src 'self'`を基本とする。scriptの外部例外は固定版katex.min.jsのURLだけ、style要素の外部例外は固定版katex.min.cssのURLだけ、fontの外部例外は同版dist/fonts/だけとし、JavaScript・CSSにはSRIを併用する。KaTeXの組版に必要なstyle属性は`style-src-attr 'unsafe-inline'`で許可し、任意HTMLを受け付ける許可とはしない。scriptのunsafe-inline・unsafe-evalを許可せず、connectはself、object・frameはnone、問題画像はselfと検証済みBlobを表示するblobに限定する。開発時だけHMRのためこのmeta CSPを外し、配布ビルドには残す。CSPとKaTeXの実描画を配布ビルドで確認する。

## 正答をブラウザへ配布する限界

学習用途では正答・解説をクライアントへ配布する。practice中のUIでは隠しても、配布JSON、開発者ツール、端末保存から閲覧できる。正答を秘匿する試験、監督、本人認証、不正防止の仕組みとしては使用しない。暗号化や難読化で秘匿できると説明しない。

## 保存・更新・互換性

正本データは編集用JSONと条件証跡で管理し、配布用catalogへ含めるものだけを列挙する。Schemaは `3.0.0` の完全一致を初期対応とし、未対応の版は説明付きで読込みを拒否する。暗黙の変換や未知フィールドの無視をしない。

将来、構造互換性が変わるときはmajorを上げ、明示的に仕様化・検証した移行だけを行う。単なるコンテンツ訂正はquestion.revisionを増やし、Schema版を変えない。新カタログは新規開始へだけ使い、進行中と過去結果のsnapshotを勝手に交換しない。

端末内データの保存・期間・削除・競合は[セッション](/sessions)、訂正・撤回・条件変更は[保守](/maintenance)に従う。

## 本体ディレクトリ構成

実際の責務を次のように分ける。

```text
src/core/          型・取得・Schema/参照検証・出題・生成・状態・IndexedDB
src/ui/            React画面・ブロック・管理された図・数式・出典・Lucide
src/generated/     Schemaから生成する検証関数（Git対象外）
public/data/       配布カタログ・JSON・WebP画像
public/notices/    本体・依存コード・CC0の原文通知
scripts/           Schemaのコンパイル・配布データ検証
tests/             出題・生成・期限・不正データの検証
docs/              仕様・一次資料・文書専用サンプル・文書サイト
LICENSE / NOTICE.md コードと素材の適用範囲
```

ライブラリのライセンス全文は本体配布物に含め、S11はその正本通知から表示する。更新時に採用版・通知・CDN URL・SRIを一緒に変更して検証する。文書サイトの依存一覧を本体の依存一覧として転記しない。

文書サイトの現状は `docs/.vitepress`、Schema・説明用サンプルは `docs/public`、検証は `docs/scripts` である。本体とドキュメントの起動コマンドを分離し、`npm run doc` を本体の起動へ付け替えない。

## 全問題の生成責務

src/core/generatorsは知識対応、計算・図条件、科目Bアルゴリズム、長文セキュリティを原問題別の固定生成関数へ分ける。原問題別IDと版をgeneration.tsへ登録し、テンプレートの入力域・基準値と照合する。図は同じ生成結果にprofile・valuesを持たせ、src/ui/SourceFigure.tsxで描く。図を独立抽選せず、図描画層で正答を算出しない。coverage検査は公式問題→基準問題→テンプレート→ミックス枠を検査し、対応漏れのあるcompleteカタログを止める。

生成対応一覧はscripts/generation-reference.tsが実際の配布データと契約から作り、doc:validateで鮮度を検査する。ブラウザにはこの編集用スクリプトを含めない。正答・生成入力は端末へ配布されるため、UIでの表示時点制限を秘匿や不正防止の保証とは扱わない。
