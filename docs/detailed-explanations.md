# 任意の詳細解説UI

## 目的と責務

通常解説 `question.explanation` を必須の構造化contentとして保持し、必要な場合だけ「詳細解説を見る」から別画面へ遷移する。問題・選択肢・関連概念を網羅的に説明する専用UIをHTML/CSS/JSで用意できる。初期表示はパラメータで指定でき、その後のタブ・選択肢・処理段階等の切替は専用UIが担当する。

共通基盤は参照解決、資源の検査、画面遷移、保存済み条件の受け渡し、隔離実行、通常解説への復帰を担当する。個々の解説内容、タブ名、パラメータの意味、切替規則を解釈しない。詳細解説は採点・練習の開始・再開の必須資源ではない。

public/explanations/host.htmlを原本とするHTMLとビルド時に出力するruntimeは、内容を持たない共通ホストである。両方の内容から共通のhashを求め、`host-<hash>.html`と`runtime-<hash>.js`として同時に配布し、本体もそのHTMLを指定する。古いキャッシュとの組合せで高さの通信が欠落しないよう、片方の変更でも両方のURLを更新する。従来のhost.htmlとruntime.jsも保持し、内容高への追従を指定しない旧本体ではiframe内のスクロールを維持する。2026年度科目A問2には[ソート解説・動作シミュレーター](/sort-explanation)、2024年度科目A問13には[アローダイアグラム解説](/arrow-explanation)を、それぞれ問題専用ディレクトリに配置する。

## 詳細解説UIの実装規約

2023年度科目A問1には[基数変換解説](/radix-explanation)を用意する。2・8・10・16進数の相互変換を分数で計算し、桁の重みと加算・除算・乗算を操作できる。同年度科目A問11の[流れ図解説](/flow-explanation)では、初期値・比較条件の変更と、変数・文字式・経路の追跡・履歴復元を行える。

本節を、既存の詳細解説の改修と今後追加する詳細解説に共通するUI実装の正本とする。依頼の初回実装から適用し、ユーザーによる冗長さ・配置・表示切替の指摘を待たずに設計・実装・検証する。個別に指定された内容や操作を尊重し、その範囲内で情報の優先順位と適切な可視化を判断する。

### DE-UI-00 — 学習の焦点と可視化を先に定める

実装前に、原問題の問い・前提・全選択肢と対象の既存解説を確認し、「何を比べるか」「どの操作で変化を確かめるか」「その結果の何に注目するか」を個別仕様へ短く記す。依頼文の項目を、そのまま常設の見出し・説明カード・設定欄へ一対一に置き換えない。

処理順序・分岐・依存関係・値の移動・式と数値の対応などは、学習上の関係が読み取りやすくなる場合に、明示的な作図・対話化の指示がなくても図・表・強調・段階表示・入力による比較へ具体化する。配置や接続そのものが意味を持つ図は、その位置関係を保つ。文章だけで十分な内容へ不要な図や再生操作を加えず、可視化を装飾やカードの数の増加と取り違えない。

基準例だけに結論や再生順を固定しない。対象問題の選択肢・条件から同じ学習対象の別パターンを列挙し、依頼範囲の理解に必要なものを同じ画面で比較・追跡できるようにする。数値・条件を変えると図・途中計算・説明・結論が連動し、適用条件を外れた基準例の結論を表示しない。扱わない内容がある場合は理由を個別仕様に記し、無関係な問題の追加や保存済み内容の変更へ範囲を広げない。

既存解説を参照するときは、目的の近いものの個別仕様と該当するHTML・CSS・JSを必要に応じて確認する。次は設計判断の参考であり、全解説へ同じ部品・配置・寸法を複製するためのテンプレートではない。

| 参照先 | 参考にする判断 |
| --- | --- |
| [流れ図](/flow-explanation) | 図中の条件ラベルを直接編集し、選択肢の関係・実行経路・文字式を同じ状態から追跡する |
| [アローダイアグラム](/arrow-explanation) | 作業・結合点・ダミーを図から選び、関係する計算・編集へ説明を切り替える |
| [基数変換](/radix-explanation) | 対応する桁を揃え、現在の計算を入力図と出力図の間へ置き、入力案内・エラー・注意を状態で切り替える |
| [ソート](/sort-explanation) | 学習目的をタブで分け、選択要素・現在の処理・完了の説明を切り替え、方式固有の補助図と詳しい補足を必要時に表示する |

### DE-UI-01 — 主図を中心に一つの作業領域へまとめる

主となる図・配列・グラフ・シミュレーションは、それだけで作業領域の横幅全体を使う。その横へ説明・状態・統計のカードを置いて図を狭めない。図、直接関係する表示操作、再生操作、現在の説明を一つのまとまりにし、図と操作を独立したカードへ分断しない。対象上で扱える簡単な編集は図へ統合し、詳しい説明・編集は図の下の領域を使う。図に収まらない内容は図の領域内でスクロール又は表示切替し、ページ全体の横はみ出しで補わない。

初期値や方式などの共通設定は図の近くへ簡潔にまとめ、入力幅は通常の値の長さに合わせる。履歴・回数・凡例は図と現在の確認対象より弱い視覚階層にし、図を妨げない余白や直後へ集約する。短い設定を大きい縦積みのフォームにしたり、副次情報のカードで主図を押し下げたりしない。狭い画面では改行・図内の横スクロール・表示切替を選び、操作対象や必要な文字を過度に小さくしない。履歴は右上、凡例は右下といった特定の解説の配置を全画面の必須条件にはしない。

### DE-UI-02 — 図と主要な操作の位置を安定させる

同じ画面幅・表示倍率では、要素の選択・解除、補足の開閉、再生ステップ、方式や表示の切替、通常の入力エラーによって図と主要な操作の位置が動かないようにする。図には必要な表示領域を予約し、拡大縮小はその内側へ適用する。保持中の値・補助配列・追加ラベルも図の設計に含める。可変長の説明・編集・補足は主要な操作より後へ配置し、内容に合わせて下へ伸ばす。説明を固定高へ閉じ込めたり、本文・説明欄に縦スクロールを追加したりして位置を固定しない。

図の予約高さ、説明の最小高さ、画面幅による切替、縮尺は内容と可読性から決め、個別仕様へ記録する。特定の解説のピクセル値を共通の固定値にしない。画面幅・文字サイズの変更や通常の予約量を超える入力エラーでは、全文を読める自然な伸長を優先する。変更後の条件でも、選択や補足の開閉によって前方の図・操作を押し下げない。

### DE-UI-03 — 今必要な説明を操作に連動して表示する

導入、現在の処理、選択した要素、完了結果、凡例、操作回数などを常時並べず、ユーザーの操作と現在の状態に合わせて表示する。再生や要素選択がある解説では、次の役割を区別する。

| 状態 | 主に表示する情報 |
| --- | --- |
| 未開始・未選択 | 操作を始めるための短い案内と必要な前提 |
| 再生・計算の途中 | 現在の処理、その理由、図の強調や値に対応する説明 |
| 要素を選択中 | 選んだ対象の値・関係・計算・編集操作 |
| 完了 | 結果と、その処理から確認できる学習上のポイント |
| 入力エラー・実行停止 | 原因、保持している有効な状態、修正・戻る・初期化などの復旧操作 |

同じ役割の情報は一か所を主な表示場所とする。入力欄・選択中の項目・図中のラベルから分かる内容を、「適用中」「現在の設定」などの常設文へ言い直して重ねない。説明には、その図だけでは分からない比較理由・途中式・変化の意味・結論の適用条件を置く。数値と文字式の対応など、照合すること自体に学習上の目的がある併記は残す。

方式の補足、詳しい凡例、回数の定義、キー操作などは必要なときに開けるようにし、同じ領域では選んだ補足に集中できるよう排他的に切り替える。短い凡例を常設する場合も主図と競合しない大きさ・位置へまとめ、可読性とコントラストを保つ。通常時の入力案内、エラー、例外時の注意は必要なものへ切り替え、意味の重なる通知や未使用枠を積み重ねない。閉じた補足や非表示のパネルを透明化だけで残さず、その内部のフォーカス・読み上げも表示状態に合わせる。読み上げ用のラベル・入力説明は別に維持する。現在の図を解釈するために不可欠な条件・単位・状態の意味は、図や現在の説明から読めるようにする。冗長さを減らすことを理由に前提を省略したり、[作問品質](/question-authoring)で解答前の表示が必要な条件を詳細解説へ移したりしない。

### DE-UI-04 — 図上の対象から選択・編集・解除する

図上の要素・ラベルを直接選択し、その対象の説明や入力へつなげる。対象を選び直すためだけの別カードや遷移ボタンを重ねない。同じ対象の再選択で解除できるようにし、閉じる操作又はEscapeでも戻れるようにする。説明や編集を閉じるときは選択元へフォーカスを戻し、確定済みの入力値を保持する。選択して読む・編集する間は自動再生を停止し、対象や値が勝手に切り替わらないようにする。

図中の短いラベルや条件をその場で編集できる場合は、その表示自体をドロップダウンなどの入力にする。長い入力や複数項目の編集は対象を選んだ先の説明領域へ置く。同じ値を図上と別の設定フォームの両方で編集させない。表示方式や比較演算子など一つの選択で成立する設定は原則として随時反映し、不要な「設定を適用」ボタンを加えない。数値入力の確定、複数項目の一括変更、計算負荷などにより明示的な適用が必要な場合は、その理由と確定単位を個別仕様へ記す。ユーザーが指定した確定方法は尊重する。

随時反映では有効な入力単位で更新し、不正入力や変換途中の入力を実行状態へ混ぜない。直前の有効な状態を保つか、結果を一時的に無効表示にするかを内容に応じて定め、入力中の値と計算済みの値を混同させない。フォーカス・キャレットを奪わず、同値の入力で不要に履歴をリセットしない。変更時に再生・履歴・選択をどう扱うかを明記する。

クリック・タップに加えてキーボードで選択・解除・適用でき、選択状態とフォーカスを識別できるようにする。操作対象は44px以上を確保し、色だけで状態を伝えない。

### DE-UI-05 — 図と説明を同じ状態から描画する

図、強調、説明、操作回数、補助配列、木構造などは同じ計算結果又はsnapshotから更新する。現在位置・選択対象・通過済み・到達不能などを区別し、確認すべき要素や直前の変化へ強調を絞る。色に加えて処理番号・矢印・枠・状態名などでも対応を示す。図の見方を切り替えるだけの操作では、入力条件・計算結果・再生位置を保持する。入力や条件の適用による再計算・初期化と、表示だけの切替を区別し、再生停止・再開・初期化・選択解除の契機を個別仕様とテストへ記録する。

学習目的が異なる内容をタブ等で分ける場合は、選択したパネルだけを表示し、非表示のシミュレーションを停止する。戻るときの方式・入力・再生位置を保持する。解説内で試す条件と保存済み問題の条件を分離し、問題・選択肢順・解答・正答・結果を上書きしない。

### DE-UI-06 — 共通基盤を使い、重複する表示を省く

アプリ内では、親画面と同じタイトル・導入・操作案内を繰り返さない。親の出典・ライセンス・改変情報と参考資料の表示は維持し、詳細解説の独自記述と原資料の権利区分を混同しない。補足を必要時だけ表示する規則を、常時表示が必要な権利情報へ適用しない。単独表示を提供する場合は、ホストなしでも必要なタイトル・案内・出典へ到達できるようにする。

埋め込みは共通の `DetailViewer` と隔離ホストを使う。本文の自然な高さをホストから認証済みの通知で親へ伝え、iframeを内容に追従させる。固定の画面高・最大高によって本文だけをスクロールさせない。タイトル、本文、解説自身の権利表示、参考資料、元問題の出典・フッターを通常の文書フローへ順に置き、画面全体で一つの縦スクロールにする。フッターの固定やsticky配置、説明欄の内側の縦スクロールは設けない。表・コード・図の横スクロールと、明示的に拡大した図の移動領域は内容の閲覧に必要な範囲で利用できる。

色、フォント、テーマ、フォーカス、半透明の前面スクロールバーは[共通の画面規約](/screens#共通色の定義と利用)に従う。標準バーやgutterのために幅を確保せず、バーとの重なりを理由に図中の矢印や操作対象を移動・縮小しない。隔離ホストと単独表示で共通実装を重複導入しない。

### DE-UI-07 — 状態遷移と操作位置を検証する

変更時は[受入条件](/acceptance#詳細解説uiの受入条件)に従い、表示制御のテストと実ブラウザでの寸法・操作確認を行う。選択・解除・補足の開閉・再生・方式切替・入力エラーを対象に、同じ画面幅・倍率で図と操作領域の位置・寸法を比較する。初期状態や一つの方式だけで完了にせず、実装した全方式・全表示モードと、有限の再生記録の全ステップを確認する。入力条件は境界・重複・長い値や説明・不正入力など、領域の寸法や状態遷移へ影響する条件を含める。

PCと狭い画面、ライト／ダーク、文字拡大、キーボード操作で、図の占有幅、値やラベルの欠け、操作対象の大きさ、フォーカス復帰、ページ全体の横はみ出し、本文・説明欄と画面全体の縦スクロールの入れ子がないことを確認する。短い画面高でも本文からフッターまで同じスクロールで到達でき、タブ・補足の開閉や文字拡大でiframeが伸長・縮小することを検証する。原問題と生成問題を扱う場合は、保存した初期条件・選択肢順と通常解説への復帰も確認する。ブラウザ面は既存の検証規約とユーザーの指定に従う。

検証した入力・方式・状態・画面条件、再現用スクリプト、成功・未解決事項と未検査範囲を[検証記録](/verification)へ残す。無限又は大きい入力域は境界と状態の組合せを選び、有限の確認を全入力の保証と記録しない。規約・文書だけの変更では問題データやパッケージを再生成せず、規約の文言を写すだけのテストや不要なブラウザ操作を追加しない。

完了前に、内容の正しさと併せて「今見る対象」「次にできる操作」「操作で何が変わったか」が各状態の実画面から分かるかを確認する。図から読める設定の重複文、不要な入力・適用ボタン、関係しない説明の同時表示、過大なフォーム・余白、読めないほど小さい凡例を点検する。初期表示だけでなく、選択・実行中・完了・エラーと対象の関連パターンを画像と操作で確認し、寸法検査が通っただけで注意の向けやすさまで確認済みとはしない。

## 問題側の任意参照と配置

参照先はアプリ配布ルートを基準とした `explanations/<問題専用名>/` とする。専用名は小文字英字で始まる3〜80文字の英数字・ハイフンで、Schemaに従う。問題ごとに専用ディレクトリを用意し、同じ原問題の年度別問題・生成用基準問題は同じディレクトリを参照できる。

```text
public/explanations/<問題専用名>/
  manifest.json
  index.html
  style.css
  main.js
  assets/
```

問題JSONへHTML/CSS/JSそのものを入れない。任意のdetailedExplanationRefにdirectory、revision、必要ならinitialParametersを保存する。次は形式の説明であり、配布問題へ登録する例ではない。

```json
{
  "detailedExplanationRef": {
    "directory": "explanations/question-example/",
    "revision": 1,
    "initialParameters": {
      "contentId": "comparison",
      "choiceId": "choice-example"
    }
  }
}
```

initialParametersは最大32項目の文字列・有限数値・真偽値である。値の意味は専用UIが定める。choiceIdは永続選択肢IDとし、並べ替えで変わる「ア・イ」を識別子にしない。省略時は空の指定を渡し、専用UIが既定の内容を決める。

参照・初期値は問題の内容hashに含まれる。参照追加時は問題改訂・関連する基準hash・テンプレート参照を更新する。旧保存問題へ参照を補完せず、正常な旧本文・通常解説・正答・結果を保持する。任意項目の追加は3.0.0 Schemaで旧データを引き続き受理し、未対応の旧アプリへの前方互換を保証しない。

## 専用manifestと資源

manifest.jsonの正本は [detailed-explanation.schema.json](/schemas/detailed-explanation.schema.json)。apiVersion=1、revision、title、attribution、filesを記録する。filesはindex.htmlを含み、相対パス・mediaType・配布バイト列のSHA-256を保持する。revisionは問題側と完全一致させ、別版へ自動追従しない。

定義や計算量を照合した資料は、任意の`references`へ表示名`title`と`sourceRefs`を記録する。資料IDは`bundle.sources`に登録した公開・確認済みの資料へ解決する。ソート解説では「参考資料（定義・計算量の確認）」という専用欄を表示し、詳細解説の作成主体・権利表示と、元問題の出典・ライセンスフッターから分ける。`references`を持たない旧manifestも受理し、その場合は参考資料欄を表示しない。転載・改変した素材の出典や権利条件は引き続き`attribution`へ記録し、参考資料欄で代替しない。

HTML・CSS・JavaScript、静止PNG/JPEG/WebP、WOFF2を扱う。最大64ファイル、各2MiB、合計8MiB、manifestは64KiBとし、8秒で取得を打ち切る。外部URL、上位パス、未宣言ファイル、種別やhashの不一致を受け付けない。SVGが必要なら管理済みHTML内のインライン要素として作成する。

共通基盤がリンクしたCSSとclassic JSを読み、隔離画面へ渡す際に展開する。画像・フォントもmanifest内の資源だけをデータURLへ解決する。CSSのurl()はCSSファイルからの相対位置で解決する。CSSの@import、画像のsrcset、外部ライブラリ・外部モジュール取得は扱わない。依存は同梱JS/CSSへまとめ、ライブラリの通知を既存のライセンス管理へ登録する。動的画像にはOpenCBTDetail.assetsのパス別データURLを使える。

base要素やiframe／object／embedの入れ子は受け付けない。専用HTMLのhttp-equiv指定は取り除き、共通ホストのCSP・遷移制限を使用する。

配布時は存在するパッケージのSchema・版・hash・サイズ・出典・素材条件・未宣言ファイルを検査する。ディレクトリ自体の欠落は任意資源なしとして許可する。未参照の専用ディレクトリやsymlinkを配布しない。catalog.filesやassetRefsへ詳細解説ファイルを混入させない。

## 画面遷移と戻る操作

[検索画面](/search)では、検査済みのパッケージをタイトル・対応問題の学習用語から検索できる。任意のmanifest.searchにsummary・keywords・textを置くと、動的に表示される解説文も検索対象にできる。Schemaの上限とmanifestの64KiB上限を守る。検索のためにパッケージのHTML・JSを実行しない。検索からの閲覧は公開問題のコピーを渡し、生成・採点・保存を行わない。練習からの以下の経路はそのまま維持する。

学習で正答を表示した現在の問題、または終了後の復習から開ける。正答表示前・時間付き練習の解答中には導線を出さない。参照先の取得・検査が成功した場合にだけ通常解説の下に「詳細解説を見る」を表示する。

経路は `#/detail/<sessionId>/<entryIndex>/<exam又はreview>`。任意のquery `initial` はJSON形式の初期表示指定であり、保存されたinitialParametersへ重ねて専用UIに渡す。共通基盤は内容切替を実行しない。問題本文・正答・生成値をURLへ詰め込まない。

遷移はブラウザ履歴へ追加する。「通常解説へ戻る」とブラウザの戻るで、同じ問題・選択肢順・解答・本文／解答領域のスクロール位置・資料の表示設定へ戻す。元画面は隠して保持する。直接URLや再読み込みでは保存sessionを検証して指定問題を表示する。無効な問題・解説へのアクセスでは詳細画面を開かない。

遷移で回答・revealed・採点を変更しない。経過時間は既存の時計の規則を継続する。詳細画面では元問題の出典・権利・改変情報を常時展開し、折り畳み操作を表示しない。詳細解説自身のattributionは別に表示する。

## 保存済み条件と初期表示の受け渡し

ホストは専用JSの実行前に `window.OpenCBTDetail` を用意する。DOMは配置済みなのでDOMContentLoadedを待つ必要はない。

| API／データ | 契約 |
| --- | --- |
| OpenCBTDetail.context.apiVersion | 接続仕様1 |
| context.question | 練習では保存済みquestion全体、検索では収録公開問題のコピー。本文・選択肢・正答・通常解説を含む |
| context.choiceOrder | 表示順の `{id, label}`。labelはその出題の「ア・イ」等 |
| context.selectedChoiceId | 保存した解答ID。未解答はnull |
| context.initialParameters | 保存指定と遷移時の指定を合わせた初期内容パラメータ |
| context.generation | 生成問題ではtemplateRef、baseQuestionRef、generatorRef、parameters。年度別元データはnull |
| context.theme | 初期のlight又はdark |
| OpenCBTDetail.assets | manifestで宣言した資源のパス別データURL |
| OpenCBTDetail.ready() | 初期描画の完了を通知する。8秒以内に呼ぶ |
| OpenCBTDetail.onThemeChange(listener) | light／dark変更の通知。戻り値の関数で購読解除 |

contextとassetsはコピーして深く凍結する。生成値は保存したinstance.parametersをそのまま渡す。基準値・最新版の生成器・シードから再生成せず、問題文を解析して値を取り出す契約にしない。parameters.valuesの位置はgeneratorRef・templateRefの入力契約に従う。

初期指定の解釈、他の選択肢・概念への切替、操作による一時的なシミュレーションは専用UIが行う。保存条件を上書きせず、操作用状態をUI内に別途作る。共通基盤はタブやステップの状態を永続保存せず、再度開くと初期指定から開始する。

## 隔離と実行

共通ホストをsandbox=allow-scriptsのiframeとして開き、allow-same-originは付けない。開発側で管理・査読したパッケージだけを実行する。通常の問題ブロック・疑似言語・データに書かれた式の実行は認めない。

初期化データは一度だけ送る。API版、接続時のランダムtoken、event.source、隔離origin=nullを照合して通知を受け取る。ホストは親windowからの初期化だけを受け付ける。隔離originへの送信はtargetOrigin=*が必要なため、自己遷移・再読み込みではデータを再送せず通常解説へ戻す。

専用ホストのCSPで外部資源、fetch等の接続、子frame、object、フォーム送信を制限する。本体DOM・IndexedDB・採点への直接アクセスを与えず、解答更新や保存の通信APIも設けない。任意コードを完全に安全にする保証ではなく、専用コードの査読・依存条件の確認を併用する。

フォーム送信は禁止されるため、入力適用などはbuttonのclickと入力欄のEnterを専用JSで処理する。submitイベントを操作の入口にしない。解説のCSSは本体のHTML準備中に非実行の符号化データとして保持し、隔離ホスト内でだけstyle要素へ復元する。本体のCSPを緩めず、コメントやJS文字列にあるstyleタグ風の文字列を書き換えない。

現在の本体は初期化時に`layout=document`を指定する。共通ホストはこの指定がある場合に初期描画後のbodyの自然な高さを測り、ResizeObserverで内容・画面幅・文字サイズによる変化を追う。`opencbt:detail:resize`（apiVersion、token、正の安全な整数height）を親へ送り、ready・errorと同じsource・origin・tokenの照合後にiframeの高さへ反映する。親viewportを下限にするscrollHeightやvh単位で高さを決めず、内容を閉じた際の縮小にも追従する。専用UIごとに親DOMの参照や独自の高さ通信を実装せず、文書ルートの高さ・最小高さをviewportへ固定しない。

本体と同じスクロール実装・CSSを適用し、標準バー・gutterを隠して半透明バーを前面へ重ねる。バー用の幅を確保せず、レイアウトを変えない。専用UIもキーボード、読み上げ、狭い画面、テーマに対応する。

共通の色は[src/ui/tokens.cssに定義したCSS変数](/screens#共通色の定義と利用)を使う。ホストは初期化時に正本のCSSを渡し、パッケージのCSSより後に適用する。テーマ変更はcontext.themeとonThemeChangeに従い、専用UIがdata-themeを更新する。HTMLを単独で表示する用途では、正本から生成したtheme.cssを同梱する。共通色の別定義や固定色のフォールバックを追加しない。

## 利用できない参照先

参照なし、旧snapshotに項目なし、404、取得失敗、サイズ超過、未対応API、改訂不一致、hash不一致、不正な資源・素材参照は、詳細解説が存在しない場合と同じ導線にする。通常解説だけを表示し、開始・再開・復習・採点を止めない。

遷移後の初期化失敗、readyの8秒超過、専用JSのエラー・未処理Promise拒否、自己遷移では通常解説へ戻り、その表示中の詳細解説ボタンを除く。S10やsession.invalidatedへ送らず、結果・回答を保持する。問題を開き直すと取得を再試行できる。

表示資源の読み込みエラーやホストCSPによる拒否も同じ復帰処理を使う。失敗通知が重なっても戻る処理は一度だけ実行する。問題JSON自体のSchema違反は既存の不正データ規則に従い、ここではSchema適合した参照先の利用可否を扱う。

旧版パッケージの長期保持やIndexedDBへの保存は必須としない。残っている一致版だけを使い、なくなった場合は通常解説へ戻る。通常解説と保存済み問題の保持は引き続き必須である。

## 検証と今後の追加

参照・Schema・経路・パラメータ・hash・サイズ・送信元・保存値のコピー・通常解説の保持をtests/detailed-explanation.test.tsで検査する。ブラウザでは配布へ含めない接続確認用fixtureを使い、初期表示、切替、戻る／進む、再読み込み、テーマ、狭い画面、隔離、失敗時の復帰を確認する。

実際の詳細解説追加には[作問品質](/question-authoring)、[内容と正答の必須テスト](/acceptance#生成内容と正答の必須テスト)、[素材条件](/attribution)を適用する。全選択肢の真偽・説明と生成入力に対する結論を独立解又は査読済み資料で検証する。基盤の成功を未作成の解説内容の正しさの確認と扱わない。

接続確認fixtureは `npx tsx scripts/verify-detail-browser.ts <起動済み本体URL>` でoutput/playwright/detailに生成する。隔離したPlaywright CLIの同一セッションでseed.js、verify.js、failures.jsをrun-codeのfilename指定で順に実行する。legacy.jsは固定高の旧本体を模擬し、新しいruntimeでも全文をスクロールして読めることを確認する。scroll.jsは収録済みの両解説を短い画面・狭い幅・両テーマで開き、タブ・補足・文字拡大への高さ追従と本文・説明欄・フッターの単一スクロールを確認する。seedは専用ブラウザのIndexedDBにだけ問題と結果を保存し、ネットワーク応答を模擬する。大きなfixtureをCLIが表示するため、出力は検証ログへ保存する。ユーザーの通常ブラウザで実行しない。
