# 問1の基数変換解説

2023年度科目A問1に、開発側で管理するHTML・CSS・JavaScriptの独自解説を追加する。資源はpublic/explanations/ipa-2023-a-1/へ配置し、検索・正答表示・復習から共通の隔離ホストで開く。原問題の設問・選択肢・正答を保持し、通常解説にC＝12、12/16＝0.75、正答ウを記す。詳細解説の図・説明・プログラムは独自作成で、原問題と解答例への参考資料リンク、独自記述の権利区分、元問題の常時展開する出典フッターを維持する。

## 入力と正確な計算

変換元・変換先はそれぞれ2・8・10・16進数。初期条件は16進数0.Cから10進数0.75、再生位置0の未開始状態とする。生成問題はgenerator-hex-fraction 2.4.0の保存済みparameters.values［変換元の基数、変換先の基数、小数部分の8分の幾つ、整数部分（10進数）］から両基数と初期値を決め、「初期値に戻す」でその条件を復元する。過去の詳細解説用の初期条件の読み取りも維持する。操作は問題・正答・結果へ書き戻さない。

生成問題は全12方向で整数部分0〜255（10進数）と小数部分1/8〜7/8を組み合わせる。全21,504条件で、各組合せを均等に抽選する。整数部は2進数8桁、8・10進数3桁、16進数2桁以内となり、全基数で1桁と複数桁の両方を扱う。例えば16進数1A.Cから10進数26.75へ変換できる。小数部は2・10進数3桁以内、8・16進数1桁で正確に表せ、循環・丸めは要求しない。原問題の「小数を変換したものを選ぶ」文章と4択を維持し、解答前に変換元・変換先を明示する。10進小数の小数部の誤答は査読済み原選択肢の相対間隔、他基数の誤答は桁の重みの入替え・補数の混同・重みの加除から生成する。整数部分が非0なら誤答の一つを変換元の整数部の最上位桁の脱落とし、整数部の変換も検査する。重複・正答との一致を除き、全選択肢の小数桁数を揃える。小数部の誤答の間隔は小数部の値から評価し、整数部を足した値への相対距離を一律に要求しない。通常解説も整数部の桁の重みと変換先での割り算を説明する。整数のみ・負数・循環小数は詳細解説で試せる範囲とする。

学習の焦点は整数部と小数部で異なる桁の重み・計算手順を同じ図で比較すること。保存条件の初期表示だけを拡張し、既存の図上の桁選択と再生・初期化を使う。設定欄や常設の補助説明は増やさず、現在の桁・計算・次に置く数字を既存の表示で追跡する。

符号付きの整数・小数・循環小数を受理し、16進数字は大文字・小文字を使える。循環部分は小数部の末尾の括弧1組で表す（例：0.(3)、0.E(6)）。整数部を省いた.5、正符号、末尾の小数点も受理する。入力上限は整数部・小数部・循環部分の合計512桁で、符号・小数点・括弧は数えない。使えない数字・括弧・小数点・空入力・超過には入力欄の近くで理由を表示し、計算操作と逆変換を無効にする。

分子・分母はBigIntで保持・約分する。負数は絶対値で途中計算し、その旨を表示して最終結果へ符号を付ける。循環前の桁数m、周期長k、循環数字列の整数値Rに対する循環全体の寄与は、R / {基数ᵐ × (基数ᵏ − 1)} とする。1周期分の有限小数とは扱わない。

出力の小数部は最大64桁。各乗算の前の残りを分子で記録し、同じ残りが再出現した位置から括弧で示す。64桁目の計算後にも循環成立を確認する。循環を確定できた結果は正確な値。残りが0にならず循環も未確定なら64桁以降を切り捨て、≈と…を付け、四捨五入ではないことを示す。その結果からの逆変換は無効にする。正確な結果でも入力上限512桁を超える場合は理由を示して逆変換を無効にする。

## 図・計算・再生

入力図・現在の計算・出力図の順に縦に並べ、それぞれ作業領域の横幅全体を使う。図は離れたカードではなく共有の罫線でつながる格子とし、各桁を1列に、重みの10進数表記・累乗・数字・10進数の寄与・状態を5行に揃える。整数部と小数部を列グループで示し、小数点と負の符号も同じ格子の専用列へ置く。数字を通常の左右順に並べ、小数点の左隣を0乗、右隣を−1乗とする。入力数字は最初から表示し、出力の未確定数字と寄与は?とする。▶現在、✓済、○未計算を文字でも表示し、現在の桁は数字だけでなく重みから状態まで列全体を強調する。入力側の重み・累乗と見出しは紫、出力側は青緑とし、計算式の対応する累乗も同じ色にする。可視化専用のローカル変数は共通の色変数を参照する。

計算順は、入力整数部の0乗→1乗→2乗…、入力小数部の−1乗→−2乗…、循環ブロック全体の加算、出力整数部、出力小数部、循環又は打切りの判定。出力整数部は商を次へ渡し、余りを0乗から左へ配置する。整数0でも1の位に0を確定する。小数部は残りに基数を掛け、積の整数部分を−1乗から右へ配置する。

現在の説明に加算前後の合計、今回の寄与、又は演算前の値・演算・数字・次へ渡す値・配置先を表示する。CではC＝12、12×16⁻¹＝12/16＝3/4＝0.75を示す。循環図は最初の1周期分の桁だけで、図の寄与の和が循環全体の値ではないことを明記する。入力の循環桁は共通のブロック加算ステップへ移動する。

「戻る」「進む」は1計算ずつ移動し、共通snapshotから図・加算合計・確定桁・次へ渡す値を復元する。桁を選ぶと対応する計算へ移動する。同じ桁の再選択、選択解除ボタン又はEscapeで選択を解除し、桁へフォーカスを戻す。計算位置を保持する。

自動再生は明示操作後に2.6秒間隔で進み、最後で停止する。「もう一度再生」は0へ戻して再開する。手動の前後移動、桁選択、入力・基数変更、逆変換、初期化、ページ非表示・離脱で停止し、タイマーと移動アニメーションを破棄する。履歴キャッシュへ入る場合も停止し、復帰後は停止した位置から手動で再開できる。監視や購読の破棄は画面が実際に破棄される場合に行う。入力変更と逆変換は再生位置0へ戻る。見出しに丸数字の段階番号を付けない。

加算では桁から計算式へ数字が移動する。小数の掛け算では積の整数部分、整数の割り算では余りを青色で示し、その数字自体を開始点として出力図の対応する桁へ800msで移動する。16進数の10〜15には数字A〜Fとの対応を併記する。連続する掛け算・割り算では、直前の「次に使う小数部分」又は商を新しい式の先頭へ650msで引き継ぎ、その後に数字を図へ配置する。移動先の数字は到着時に表示し、取り消し時は隠した文字と強調を復元する。変換結果と現在の桁・確定する数字は共通の青色変数を参照し、紫・青緑の重みと区別する。式は正確に表示できる10進小数・循環小数を使い、長い循環になる場合は分数で表示する。動きを減らす設定では移動を省き、同じ計算・操作を維持する。

確定した桁・未確定の?・各桁の寄与は図で確認する。別の途中結果欄は設けず、加算前後の合計や次に使う商・小数部分を「小数部を掛け算で求める」などの現在の計算説明へまとめる。循環図が1周期分である注意も同じ説明欄に表示する。桁の選択時には、図で省略された長い値だけを全文で補足する。「全体の計算を確認」は入力の分解式と、計算・次に使う値・確定数字と配置先の計算表を開く。

## 寸法と操作性

入力欄と基数を上部左、変換結果と逆変換を上部右へ置き、独立した結果エリアを設けない。入力案内・エラー・循環又は切り捨ての注意は、その下の共通枠で必要な一つを表示する。枠の最小高さは、行間1.5でPCの2行分（3em）又は540px以下の3行分（4.5em）に下余白8pxを加え、未使用のエラー欄や通常結果の注意書きへ別々の空白を確保しない。620px以下では数値・変換元・変換先を一行にまとめ、入力案内の下へ変換結果を置く。

図は各13.5remの水平閲覧領域を予約し、行見出し・列の幅・行の高さを共通にする。行見出しは横スクロール中も左端へ残し、現在の桁が見出しの背後に隠れないように表示位置を調整する。列の間隔やカードの角丸を設けず、同じ列の重み・累乗・数字・寄与・状態の左右端を一致させる。文字拡大時は図の予約量もremに追従する。長い数の桁は省かず、図内だけを横スクロールする。長い重み・寄与は格子内で短縮し、重みは正確な累乗でも示し、寄与は桁の選択先に全文を表示する。

再生操作とステップ数は入力案内の下、入力図と出力図の上へ置く。DOMも同じ順序にし、キーボードで入力から再生操作、図へ進める。計算は入力から出力へ至る中間状態として両図の間に置き、各図との隙間を小さくする。凡例と計算順序の補足は出力図の後へ置く。PCのステップ数は右端の一定幅へ置き、文字数が変わってもボタン位置を変えない。計算欄の高さは、現在の入力の全ステップと桁選択時の内容を実際の幅でまとめて測り、その最大値を確保する。同じ入力・幅で選択・前後移動をしても出力図を上下させない。入力や幅・文字サイズの変更時は測り直す。長い分数も省かず折り返し、一つのページスクロールで読める。説明内の縦スクロールや固定フッターを設けない。

620px以下では数値・両基数を一行、再生ボタン4個も一行に配置する。戻る・進むは幅44pxとし、完了後の再生は「もう一度」、初期化は「初期値」に短縮する。読み上げ名は「もう一度再生」「初期値に戻す」を保持する。ステップ数はボタンの上に置く。320pxでも図・表内の水平スクロール以外にページ全体の横はみ出しを作らない。ボタンと入力の高さは44px以上。数値と結果を読み上げられるラベルとライブ領域、指数の上付き、基数の下付き、分子・分母を分離した分数を使う。色・フォーカス・スクロールバーは共通実装を使う。単独HTMLのテーマとスクロール実装は生成した複製で、本体では共通ホストが提供する。

## 改訂と検証

原問題は詳細解説パッケージ改訂3への参照更新により改訂5、基準問題とテンプレートは改訂11、生成器は2.4.0とする。基準hash・セット参照・カタログを更新し、旧保存内容へ詳細参照を補完しない。過去版の本文fixtureは保持せず、非互換の履歴は最新版による別の学習へ切り替える。原問題の本文・全選択肢・正答・通常解説は維持する。

tests/radix-simulator.test.tsは、独立した「桁列全体をシフトした値の差」の参照式で有限・循環入力と出力を照合する。指定5例の往復、全16基数組合せの符号付き有限・循環512ケース、ステップ順序・加算・除算・乗算・残り・前後移動、512桁、64桁の終了・循環・省略境界、無効入力、保存済み条件、旧記録の再開・追加・復習、パッケージhash・共通資源を検査する。有限の選定範囲の検証であり全512桁入力の全列挙とはしない。

`npx tsx scripts/verify-radix-browser.ts <起動済みURL>` でoutput/playwright/radixにverify.js、layout.js、generated.js、breakpoints.js、motion.jsを生成する。隔離したheadless Playwright CLIで、各ファイルをrun-codeのfilename指定で実行する。verify.jsは再生用のタイマーだけを隔離ブラウザで仮想化し、描画と高さ通知の時計を止めずに再生・停止を検査する。motion.jsは移動の開始点と到着点、引き継ぎ、色の対応、割り算の商・16進数・循環・中断・動きを減らす設定を検査する。画面検証はlayout-1362.js、layout-1280.js、layout-390.js、layout-320.jsへ分割して実行できる。1362px幅は注釈時と同じ1313px高で、両図と現在の計算が同じ画面内へ収まることも検査する。breakpoints.jsは540・620・800pxの切替の前後を含む10幅×両テーマの単独表示で、不正入力・全ステップの操作位置を検査する。生成問題の確認は専用ブラウザのIndexedDBだけにfixtureを保存する。全ページ画像は対象幅を維持して撮影時だけ画面高を本文の高さへ広げ、Chromiumの隔離iframeが画面外で未描画になる影響を避ける。資源変更後は `node scripts/update-radix-manifest.mjs` で共通資源の複製とmanifestを更新し、`npm run check` を通す。実測結果と検査範囲は[検証記録](/verification)へ残す。
