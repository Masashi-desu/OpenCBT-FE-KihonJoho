# トランザクションの状態遷移

2019年度秋期 基本情報技術者試験 旧制度・午前 問28の専用解説をpublic/explanations/ipa-2019-autumn-am-28/に配置する。通常解説・復習・検索から共通の隔離ホストで開く。2進数変換解説のsnapshotによる段階移動と図上の選択、流れ図解説の経路比較を参考にする。追加ライブラリは使わない。

## 学習の焦点と操作

「処理中」と「済」を区別し、一つのトランザクションが確定又は取消しを完了するまでの遷移を比較する。正常コミット、アクティブからのアボート、コミット処理中の障害の三経路を用意し、戻る・次へ・スライダーで一遷移ずつ往復できる。五状態と五つの許可遷移を同じ図に固定し、現在の状態に「▶ 現在」、直前の矢印に太線を付ける。状態の枠を直接選ぶと、その状態の意味と可能な次の処理へ説明を切り替える。

主図は全幅で使い、説明・選択肢を横に並べない。図は840×380の座標を使い、52.5〜65.625rem（通常840〜1050px）の可読幅を確保し、文字拡大では図自体も拡大する。狭幅は図内だけ横スクロールし、段階移動時に現在の状態を表示範囲へ入れる。選択肢を選ぶと対象の状態対の中心へ横表示を合わせ、解除すると現在の状態へ戻す。図と操作は全ステップで同じ位置・寸法を保持する。可変長の説明、全選択肢、用語補足を主要操作の後に置き、説明は自然に下へ伸長させる。図上の対象は180×72pxで、補足・入力・ボタンは44px以上とする。共通ホストの内容高通知と単一ページスクロール、共通色、前面スクロールバーを使う。

原問の四選択肢は行を直接選んで比較する。起こり得る遷移は実線、起こらない遷移は破線と×で図に重ね、同じ説明領域で理由を示す。原問題の正答はイ（アボート処理中→コミット処理中）。コミット完了前の障害によるアボートと、完了後の補償を区別する。選択中も再生位置は保持し、同じ対象の再選択・選択解除・Escapeで解除して選択元へフォーカスを戻す。段階移動は選択を解除する。経路選択は随時反映し、その経路の先頭へ戻す。最初からは正常コミット経路の先頭へ戻す。自動再生や数値編集は設けない。初期状態の短い操作案内、途中の遷移理由、完了結果、選択対象の説明を排他的に切り替える。

開始後の五状態を説明するモデルであり、製品ごとの内部状態や分散トランザクションの詳細は範囲外。再実行・補償は別のトランザクションとして説明し、完了した元トランザクションへの復帰に見せない。

## 保存条件と権利

生成器generator-source-2019r01a-fe-am-28@3.2.0の保存済みparameters.values[0]（0〜3）から、不可能な遷移の四種類を復元する。0はアボート処理中→コミット処理中、1はアボート処理中→コミット済、2はアボート済→コミット済、3はコミット済→アボート処理中。保存したchoiceOrderのIDと表示記号を使い、再抽選や本文解析を行わない。解説の状態を保存済み問題・選択肢・回答・結果から分離する。未対応の生成条件はホストのエラー処理で通常解説へ戻す。

2026-11-05にIPA公式の[問題冊子](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000dict-att/2019r01a_fe_am_qs.pdf)物理p.16、[解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000dict-att/2019r01a_fe_am_ans.pdf)p.1、[FAQ](https://www.ipa.go.jp/shiken/faq.html)の過去問題利用条件を再取得した。PDFのSHA-256は既存Source記録（問題4cd40465…、解答074c4437…）に一致。発行主体はIPA、PDF固有の公表日・更新日の明記は未確認。FAQの最終更新は2026-09-02。問28の本文・五状態・前後二列表・全4択と正答イを照合した。第三者図表・引用文・規格文言は当該問題で識別せず、既存の素材別権利を継承し、出典・改変表示付きの教材同梱・表示・改変として扱う。既存画像bytes・原文・通常解説・生成器は保持する。独自の図・説明はCC0-1.0、コードはMITであり、IPA原資料と区別する。同一AIの検算・査読で、第三者査読や個別許諾取得とは扱わない。

原問題・基準問題・テンプレートは改訂2とし、詳細参照、派生参照、基準hash、関連セット参照、配布hashを更新する。変更記録の重複answerDetailsは除去する。本文・通常解説・選択肢・正答・生成器版・入力域・採点・保存形式は保持する。非互換履歴とブックマークは既存の現行版参照規則に従い、旧回答を再採点しない。

保存済み問題の実画面検証で、既存のacquireRunLockがWeb LocksのifAvailableとsignalを併用し、実ブラウザでNotSupportedErrorになる不具合を再現した。待機列に入らないifAvailableだけを渡し、タイムアウト・解除後の遅いcallbackはローカルの取消し状態でロックを保持しないようにした。公開API・排他方針・保存形式は維持する。tests/browser/storage-browser.test.tsで実際のロック取得・競合・解放・再取得・即時解除を検査し、機能別の保存検査も対象に加える。
